### 2.2 定案：`pinned` 标签错，同一 arena，pageable 路径

**办公室独立读码**（本地 `origin/engine-main = fe8d5bf`，`src-tree/fusion-engine-src`）：

```
program_impl.cpp
  L391   std::size_t reserved_bytes = plan.context_cache.host_kv_capacity_bytes;
  L400   const char* pageable_env = std::getenv("NINFER_HOST_PAGEABLE");
  L401-2 const bool pageable = pageable_env && ... != '0';
  L404   if (!pageable) {                      ← 仅非 pageable 才 clamp
  L405-7     reserved_bytes = clamp_host_kv_reservation_bytes(...);
  L413-17 if (reserved_bytes >= minimum_stride)
             host_kv_arena = std::make_unique<HostKVArena>(reserved_bytes, layouts);

arena.cu
  L636   const char* pageable_env = std::getenv("NINFER_HOST_PAGEABLE");
  L637   if (pageable_env && ... != '0') {
  L638       void* pageable_ptr = std::malloc(size_bytes);   ← 不是 cudaMallocHost
  L646       pageable_ = true;
  L647       return;                                        ← 提前返回，跳过 pin 路径
```

**三层结论**：

1. **两段引用是同一个 `reserved_bytes`、同一个 `HostKVArena`**——不是「KV payload vs staging」两个缓冲。§234 引的 `:367-394` 是 pinned 路径的 WDDM clamp 注释块，`:400-407` 是它的 guard。**⇒ 我 v2 里留的那个问号可以销了。**
2. **现役 `HOST_PAGEABLE=1` ⇒ `std::malloc` ⇒ pageable**，代码注释原文：「pageable host memory is charged to system RAM only, so the WDDM-driven clamp does not apply to it」（L397-399）、「pageable memory is not mapped, so it is charged to system RAM only」（arena.cu L631-632）。
3. **⇒ §234 L7255 的「pinned」是标签错误，应改 pageable**；由此推出的「系统 RAM 被 pinned 钉死」也应改成「pageable 被系统换出」。

**修法方向的连带结论**：TELE 原候选「改非 pinned」反向。代码注释 L381-382 明写：pinned 会与模型争显存，「**默认 8 GiB 都无法与本项目任何模型共存**，服务拒绝启动」——现役 16 GiB 更是直接不可能。可测替代见 2.4。

**边界（如实声明）**：本地快照 = `c5f48a8 line`（11-12），§234 引的 `352f27a`（11-14）本地不可得（fetch 被重置）。该段行号在 11-12 → 11-15 两次携入间未漂移，语义稳定；**家里在现役位跑一次 `env` dump 确认 `NINFER_HOST_PAGEABLE=1` 即可销账**（TELE 云端已给预期读数）。

### 2.3 由此收敛的假说分支


### 2.6「Windows 特有」→「默认策略差异」

Windows 的 VidMm 会把**空闲高占用进程**当可修剪对象；Linux（amdgpu TTM / NVIDIA sysmem fallback）也有超额路径，但没有「空闲期主动 trim 一个空闲 compute 进程」这个默认动作。**⇒ 移植能绕掉 trim，绕不掉超额。**

## 三、判据体系（v3 重排）+ 两条机制修正

### 3.1 判据 A 的判别力被推翻（本轮最关键）

v2 写「空闲后 `used_memory` 降 ≥200 MiB ⇒ 逐出成立」——**这条对主假说无效**：

```
host KV 是 pageable ⇒ 不计入 nvidia-smi used
⇒ 它被 OS 换出时，used 不会下降
⇒ A 的「无变化」不能证伪主假说，只能说明「设备侧没被逐出」
```

**修订后的判据分工**：

| 判据 | 测的是哪条线 | 成立条件 | 不成立的含义 |
|---|---|---|---|
| **C** Sysmem Fallback 状态 + decode 复测 | 容量账是否失真 | 见 3.2 四态 | — |
| **B** `Pages Output/sec` + 分盘写带宽 | **主假说**（pageable 被换出） | 慢态时抬升且某盘写饱和 | 无抬升 ⇒ 主假说降级（转设备侧） |
| **A** 空闲前后 `used_memory` | **副线**（设备侧逐出） | 降 ≥200 MiB | 无变化 ⇒ 副线排除，**主假说不受影响** |
| **D** ETW GPU + Kernel-Memory | 主/副线同时（soft fault + evict 事件） | 停顿窗出现 evict / paging ≥30 s | 证伪 ⇒ 转备择（见 3.4） |
| **F** host KV 预算对照 | 修法有效性 | 8 GiB 下自愈时间缩短 ≥50% | 无效 ⇒ 回填面不是主因 |
| **E** HAGS ON/OFF | 调度层 | OFF 后不复现 | 转 VidMm 层 |

**⇒ 顺序改为：C → B → A → F → D → E。**（A 从「一锤定音」降为「排除副线」，成本仍 1 分钟）

### 3.2 判据 C：从三选一到四态（LUMMY 补第四态）

| C 的结果 | 判定 |
|---|---|
| Fallback 关 | 池全在显存，容量账可信；慢态只能走 pageable 被换出这条支线 |
| Fallback 开 + decode 明显下降 | **容量账失真**，126,976 需重算，「吃满物理边界」表述撤回 |
| Fallback 开 + decode 仍 183.6 + used 不变 | fallback 未对热池生效；容量账可信，「free 0 B 仍起服」需另解释 |
| **Fallback 开 + used 下降 + decode 不降**（第四态） | **选择性 fallback**：只挪冷页/非热池分配 ⇒ 容量账仍可信但机制需修正；**且说明驱动 fallback 与 KVMem host 环可能天然隔离** |

**办公室补一句机制解释**（支撑第四态为何可能）：Sysmem Fallback 作用于 `cudaMalloc` 这类**设备分配**；host KV 走 `std::malloc`（L638），**根本不进 VidMm 的分配表**。所以「双重 host 化」不是两套机制互相打架，而是**两者共同挤系统内存/commit**（见 3.3）。

### 3.3 双重 host 化：从「机制交互」降级为「commit 竞争」

```
① KVMem host 环   = std::malloc，pageable，占系统 RAM/commit（不计显存）
② 驱动 fallback   = 设备分配在主存紧张时落 sysmem，占 commit + PCIe
共同点：都吃 commit / pagefile；不同点：②才进 VidMm 表，①不进
```

**⇒ 风险从「驱动与 KVMem 互相 trim」改为「两者叠加把系统 commit 推高 ⇒ pagefile 压力上升 ⇒ 回填更慢」。** 判据仍是 C 的三读数：`cudaMemGetInfo` free、`nvidia-smi` used、**系统 commit charge**。

### 3.4 判据 D / E 预注册（TELE 云端设计，办公室采纳）

**D（ETW/GPUView，零配置变更，可插入任何等待窗）**

```
wpr -start GPU -filemode
请求 #1 → 停 ≥5 分钟（精确到秒）→ #2 → #3 → #4
wpr -stop trace.etl
```

- **证实线四条**：① 停顿窗内出现 evict/trim 事件；② #2 的 paging 段 ≥30 s；③ #3/#4 自愈（paging 归零）；④ 日志侧静默段同步衰减
- **证伪线 → 备择**：加录 `Kernel-Memory` provider 查 **pagefile soft fault**（若 env dump 确认 pageable，首轮就把两个 provider 一起录，省一次二轮）

**E（HAGS）**

```
E0（零成本顺手）：记录 CUDA Sysmem Fallback Policy 当前值
HAGS OFF → 重启 → 完整重跑 D-1
证实线：定位调度层；证伪线：转 VidMm 层
```
