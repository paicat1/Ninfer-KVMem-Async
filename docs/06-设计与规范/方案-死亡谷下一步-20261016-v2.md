## 2. 核心未验混淆：**我们的窗口，是不是我们自己造的？**

**动机（三条线索）**：
1. **按需触发随时有效**（外部 400–1200 MiB ⇒ 谷）⇒ 机器**一直**处于"可被推入谷"的状态 ⇒ 自然谷只需一个额外压力事件；
2. **深谷（verify 1539–2532 ms）出现的时段（01:17–01:22）正是我自己的 `night_ab`/`trigger_test` 在施加 600 MiB 显存占位的时段**（`arm_*` 台账在案）；
3. **00:31–00:38 那次自然谷，与我施加 32 GiB 宿主内存压力（`memhold.py`）的时间重合**。

**反证（一条，但很强）**：`S12` 的 8.5 小时**连续深负载**（探针+长请求）**零谷** ⇒ "推理负载本身"不诱导谷。
⇒ 但 S12 只排除了"推理负载"，**没有排除我的其它工具**（`vram_hold` / `memhold` / GPU 微基准 / 频繁重启 / 构建）。

**⇒ 本方案第 2 步就是把这条混淆算清楚（离线、零成本）。**

## 3. 三步（全部有界、有判据、有终止）

### 第 1 步｜修仪表：`window_watch.py` 新鲜度（~30 min）

**改什么**：
1. 记录上次采样的 **日志行数**（`lines=`），本次只在**新增行**里找 `target-split` / `throughput`；
2. 无新增行 ⇒ 字段写 **`stale`**（显式），不再复读旧值；
3. `stamps` 改为 **`(行号, 时间戳)`** 或新增 `fresh=0/1` 列；`s13` 同理；
4. 台账首行写明工具版本与判据（防"哪版台账"歧义）。

**判据（先验）**：修后台账在引擎空闲时**必须出现 `stale`**；引擎出慢轮时**必须出现新值**（且与探针同刻一致）。
**终止**：改完跑 5 分钟对照（空闲 + 一次探针）即验毕。

### 第 2 步｜**自诱导混淆审计**（离线，~30 min，**本方案重点**）

**做什么**：把两条时间线叠起来，逐段判定"谷出现在我们活动期还是空窗期"。

| 线 | 数据源 |
|---|---|
| **① 谷事件线** | 全部 `logs\test_valleywatch*.log(.old)` 的 `verify` 分层统计（我已有脚本口径：轻 30–100 / 谷 100–226 / 深 226–500 / 极深 ≥500）**按归档时段** |
| **② 我方活动线** | `.temp\*` 台账的 mtime（`vram_hold`/`memhold`/bench/`long_hold`/`dose*`/`night_ab` 等）+ `git log --since` 提交时间 + 引擎起服时刻（日志 `engine ready` 行） |

**判据（先验，写死）**：
- 若**深谷（≥226 ms）事件 100% 落在我方活动窗口内**，且**空窗期零深谷** ⇒ **自诱导假设成立/高度可疑** ⇒ 转第 3 步的 A 组（禁工具对照）；
- 若**存在至少一次深谷落在"我方完全无活动"的时段** ⇒ **自诱导假设被削弱** ⇒ 自然源在机器侧，转第 3 步的 B 组（1 s 粒度机器采样）。

**终止**：审计出结论即止（无论哪边）；产物=一张时段对照表 + 判定。

### 第 3 步｜受控自然窗观测（**仅在用户授权时段**，预算=用户给）

**A 组（若第 2 步指自诱导）**：**禁工具**对照——引擎 + 每分钟 1 探，**除探针外不跑任何我的工具/构建/重启**；预算建议 2–3 h。
**B 组（若第 2 步指机器侧）**：**1 s 粒度机器采样**（进程/句柄/驱动计数/显存）+ 每分钟 1 探，找"窗口开启那一刻什么变了"。
**共同判据**：`fresh verify ≥30 ms` 或 `decode < 60`（**必须来自修好的仪表或探针本身**）；记录谷的起止与边界事件。
**终止**：到点即收；**无谷也交付**（"未复现 + 完整新鲜时间线"）；**不得自动延期**。
