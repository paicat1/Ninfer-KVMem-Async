# 术语与工具分工：守望者 / 猎人 / 看门狗（以及配套的"枪 / 压 / 尺"）

- 作者：桌面版 CodeBuddy（CB）· 2026-10-17
- 目的：这几天工具越来越多，用途容易混。**此件把"谁发请求、谁只观察、谁保证观察不断"写死**，
  供 CB / TELE / CLI 与后续会话共同引用；新增值守类脚本须回来更新此件。

## 一、三件套（值班时在跑的就是这三个）

| 层 | 名字 | 脚本 | 发请求？ | 改配置/注压力？ | 回答的问题 |
|---|---|---|---|---|---|
| **观测层** | **守望者 Watcher** | `scripts/window_watch.py`、`scripts/valley_watch.ps1` | ❌ **不发** | ❌ | **"机器现在什么状态？"** |
| **驱动+判定层** | **猎人 Hunter** | `scripts/valley_hunter.ps1` | ✅ **定频发**（1 发/分钟，参数固定） | ❌（一级只冻结快照） | **"谷来了吗？证据在哪？"** |
| **元监控层** | **看门狗 Watchdog** | `scripts/watchdog_hunter.ps1` | ❌ | ❌ | **"前面那两个还活着吗？"** |

### 1）守望者 = 系统面"记录仪"（只读、零负载）

- 每分钟一行：GPU（**时钟 / 功耗 / util / 显存**）+ 主机态（freemem / pagefile / CPU / top 进程）+ 引擎日志里的 decode/verify；
- **不发任何请求** ⇒ 自己不制造负载 ⇒ **不会诱发谷**，是"干净的背景记录"；
- ⚠ 因此**单独靠它发现不了谷**——谷只在**有负载**时才显现（见 §三）。

### 2）猎人 = 诱饵 + 判据 + 抓案卷（主动、受控）

- **定频计量驱动**：固定 1 发/分钟、参数恒定（filler 45 KB / max-tokens 200）⇒ **既当诱饵又当测量**；
- 命中预登记判据（`decode<60` + 相对功耗辅证 + **连续 2 拍**）⇒ 秒级冻结现场、落案卷到 `.temp/cases/case_<时间戳>/`；
- ⚠ 它是"我方活动" ⇒ 但**定频驱动是可控基线负载，不算混淆**；真正的混淆源是**非定频工具活动**（构建 / 压力工具 / 桌面占用 / 重启）。
- 前身：`scripts/observe_A.ps1`（限时 180 分钟收窗版）；猎人 v2 改为**不收窗、案件驱动**。

### 3）看门狗 = 盯"观测本身有没有悄悄死"

- 每 120 s 查猎人台账的 mtime；**先看引擎进程在不在**（引擎没了是另一类 `ALERT(ENGINE)`），引擎在而台账停更 ⇒ 判"猎人静默死亡"；
- 落告警到 `.temp/cases/WATCHDOG_ALERT.txt`；
- 存在理由：本仓被"常驻件静默死"咬过（S13 计数停摆、陈旧值拖 12 h）⇒ **"零捕获"极可能是"观测已死"的假象**。

## 二、配套的"枪 / 压 / 尺"（不属于三件套，是它们调用或对外用的工具）

|---|---|---|---|
| **枪（探针）** | `a2gate.py` | 配对跑，返回 decode / wall / verify | **猎人用的就是它** |

## 三、为什么必须三层（缺一层会怎样）

| 缺哪层 | 后果（都是这周真实踩过的） |
|---|---|
| **缺守望者** | 只有探针读数，**没有系统面对照** ⇒ 无法做机器侧归因（功耗/时钟/freemem 谁变了） |
| **缺猎人** | **没人发负载 ⇒ 引擎空转 ⇒ 谷构造上不可能出现** ⇒ "无谷"是**零信息**（今晚 03:20 那次差点被误记成"空转盲窗"） |
| **缺看门狗** | 猎人静默死而无人知 ⇒ **"零谷"是假象**（今晚因此差点误判） |

## 四、一条容易踩的口径（已写死）

**同一个引擎同一时刻有两个"decode"，差约 4 倍**：

- **a2gate 探针**：单请求生成速率（200 tok / 实耗 ~1.2 s ⇒ **165**）—— **判据用这个**；
- **引擎 throughput 行**：**固定 5.0 s 窗口平均**（199 tok / 5.0 s ⇒ **39.8**）—— window_watch 取这个，字段已改名 **`decode_win5s`**。

⇒ 拿 `decode_win5s` 去套"decode<60=谷"，**健康会被误判成谷**。所有判据文档一律标注口径。
