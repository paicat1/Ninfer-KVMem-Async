# 分析：慢态（6–7× 整机降速）的 P-state 假说与判别程序（CB，20261027）

> **性质**：零机时纸面分析 + 可执行判别程序。**假说未实测**，判据先于数据。
> **对象**：挂账 #58「慢态 6–7× 触发源判定」——当前最大速度杠杆。
> **证据基线**：§164/§167（两晚同件同负载同 sha、6–7× 差）、§172（`pre-run gpu: 772, 36, 15791, 16303`）、§174（N0 功耗 194–215 W vs 251–268 W；E1/E2 排除降池与 exe 回退）。

---

## 〇、一句话

**慢态不是算力问题，也不是热/功耗墙——是 GPU 停在 P8 待机频率（772 MHz）没升到 P0（≈2617 MHz），并由"利用率采样 → 不升频 → 更慢 → 采样更低"的正反馈锁死。** 一条 `nvidia-smi -lgc` 可能根治它。

---

## 一、观测特征：它们指向同一个答案

| 观测 | 数值 | 含义 |
|---|---|---|
| `clocks.sm`（慢态跑前快照） | **772 MHz** | RTX 5080 boost ≈ 2617 / base ≈ 2295 MHz——772 是 **P8 待机频率**，不是"降一点"，是"没升频" |
| 功耗 | 194–215 W（正常 251–268 W） | 没吃功率预算 ⇒ **不是 SW/HW Power Cap** |
| 温度 | 35–37℃（凉） | 不是 HW Thermal Slowdown |
| 输出 sha | 跨日逐字一致 | 计算正确，只是慢 ⇒ **GPU 在等，不在算** |
| 速度差 | 6–7× | 2617/772 ≈ 3.4×（频率）+ 等待放大 ⇒ 6–7× |

**GPU 在跑 kernel 却停在 P8**——只可能是驱动没把它升上去（或升了又被压回来）。

---

## 二、为什么"时有时无"：正反馈回路

```
kernel 起步慢（低频）
  → 每步耗时长
  → WDDM 短窗利用率采样偏低（或 host 提交路径阻塞，GPU 空转等）
  → 驱动判定"负载不足" → 维持/回落到低 P-state
  → 更慢 → 采样更低 → 锁死
```

触发条件全部可变，这解释了"同一台机器两晚差 6–7×"：

- 开机后第一段负载的形态（首个 kernel 太短 ⇒ 驱动没判定到压力）；
- Windows 电源计划（默认 **balanced** 会压 GPU/CPU 时钟）；
- NVIDIA 控制面板电源管理模式（"自适应"vs"优先最高性能"）；
- 后台监控/RGB 软件轮询 GPU 传感器 ⇒ DPC 延迟 >1000 μs 打断 GPU 驱动（"无事可做"→ 降频）；
- 驱动版本 / persistence mode 关闭（P-state 反复初始化）。

## 三、三个候选与判别（按可能性）

| # | 候选 | 判别方法 | 成立特征 |
|---|---|---|---|
| ① | **P-state 未升**（最可能） | 慢态时 `nvidia-smi -q -d PERFORMANCE` 看 `Clocks Event Reasons` | `Idle` = Active，或 `clocks.sm` 恒 772 |
| ② | **DPC 延迟打断** | LatencyMon 跑 5 分钟 | 任一驱动 DPC > 1000 μs |
| ③ | **pinned 内存退化**（会伪装成慢态） | 慢态时看 `demote profile` 的 `copy=` | 正常 2.68 ms，退化显著变大（staged 阻塞拷贝） |

③ 的机制：`NINFER_HOST_PAGEABLE=1` 下若 pinned 分配失败，`cudaMemcpy` 退化为 staged 拷贝——**也能造成 6–7×**，且与 P-state 无关。必须先排除它，否则锁频实验会误判。

---

## 四、决定性实验（先做 ① 的判决，成本 5 分钟）

```powershell
# 0) 记录基线
nvidia-smi -q -d CLOCK,PERFORMANCE,POWER > .temp\gpu_base.txt

# 1) 开启持久模式（防 P-state 反复初始化）
nvidia-smi -pm 1

# 2) 看支持的频率组合，选一个下限（不低于 base）
nvidia-smi -q -d SUPPORTED_CLOCKS

# 3) 锁频：下限 2000 MHz，禁止掉到 772
nvidia-smi -lgc 2000,2617

# 4) 同负载重跑（async_abab 或 a2gate deep 3 轮），对比 decode
#    跑完还原：nvidia-smi -rgc
```

**判读**：

| 结果 | 定性 | 处置 |
|---|---|---|
| 慢态消失、decode 回到 275+ | **① 成立** | `-lgc` 写进 `engine_ctl.ps1` 的 start 动作，永久生效；#58 降级为"启动脚本缺一行" |
| 慢态照旧、但 `copy=` 显著变大 | ③ 成立 | 查 pinned 内存分配（`cudaHostAlloc` 失败路径 / 内存碎片） |
| 慢态照旧、`copy=` 正常 | 转 ②（DPC）或更深的驱动同步 | LatencyMon + 驱动版本比对 |

配套（零成本）：Windows 电源计划 → **高性能/卓越性能**；NVIDIA 控制面板 → 电源管理模式 → **优先最高性能**。

## 五、如果成立，意味着什么

1. **#58 从"最大速度杠杆/未解之谜"降级为"启动脚本缺一行"**——不是引擎问题，不是硬件问题。
2. **历史慢态数据全部重估**：§164 的 27.4 tok/s、§167 的"6–7× 差"都是"GPU 没升频"的读数，不是引擎性能。**"2 倍"这个数字本来已作废，现在连"慢态下异步仍有 2 倍"这个观察也要重新标注为 P8 态读数**。
3. **速度预期不再打折**：P0 下的实测是 +19%（正常态），上限估计 460–500（浅载，draft4 高接受率）/ 300–350（深载 152K，restore 优化后）。
4. **所有 A/B 实验必须加 P-state 前置检查**：跑前 `nvidia-smi --query-gpu=clocks.sm,clocks_event_reasons.active,power.draw --format=csv` 一行，`clocks.sm < 2000` 或 `Idle=Active` 即判"不是 P0，作废重跑"。这比"decode<60"早得多，也比"功耗<230 W"更直接。

---

## 六、边界与分账

- 本件是**假说 + 判别程序**，未做任何实测；"772 MHz = P8"依据 RTX 5080 规格（boost 2617 / base 2295）与 §172 的单次快照推断，**样本 n=1**。
- 与死亡谷（Gen5+外压≥400MiB+贴边，提交路径阻塞）**可能是两个不同现象**：谷有明确的触发三条件，慢态是"整机降速且与负载无关"；但两者都表现为"GPU 在等"，**不排除同源**（都在等 host/驱动）。若锁频实验同时消掉谷，则"同源"成立，谷的攻关方向要重写。
- 若锁频无效，本件作废，转 DPC / pinned 内存 / 驱动内部同步三条线。
