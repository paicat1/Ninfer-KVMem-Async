# 规程：交付前六条硬检查（防复发）

- 日期：2026-10-29
- 性质：**作业规程**——动手前逐条对照，不是事后解释
- 适用范围：本仓 + 附属仓库（`engine-src`）
- 立规背景：源码树位置误判（记录在案却未查阅）；源码树改动长期未归档（`CMakePresets.json` 的 arch 两行）

---

## 零、为什么要有这一页

已反复验证：**"我会注意"等于零**。以下六条每条都带「触发 / 动作 / 校验」，**能机械化的已进闸门**（标 ✅），不能机械化的只能靠本页清单在动手前对照。

---

## ① 禁猜路径（无闸）

- **触发**：任何涉及"路径 / 位置 / 是否存在"的判断
- **动作**：先从记录读——`docs/`、`build/README.md`、`.gitignore`、`git ls-files`；**禁止凭印象**
- **校验**：断言"不存在"时，必须同时给出「已查位置清单 + 探针命令 + 未命中输出」，缺一即违规
- **案例**：曾只查根目录 `src-tree` 就断言"源码树不在本地"；而 `docs/01-构建与发布/规范-引擎编译配方-正确姿势与配方级事故-CB-20261020.md` L14 明写「源树读 `engine-src\src-tree\fusion-engine-src`」

---

## ② 改动即归档 ✅ 闸（SUBREPO-CLEAN-GATE）

- **触发**：任何对源码 / 配置 / 脚本的改动
- **动作**：当轮必须落库；**工作区留改动 = 未完成**
- **校验**：**所有仓库** `git status --porcelain` 为空（主仓 + `engine-src`）
- **案例**：`engine-src` 的 `CMakePresets.json` 中 `CMAKE_CUDA_ARCHITECTURES=120a` / `NINFER_SM120_NATIVE=ON` 两行长期未提交 ⇒ 源码树一旦重克隆，CMake 默认 sm_86 ⇒ RTX 5080 JIT 长征假死复发（§128）

---

## ③ 历史文件只增不删（无闸）

- **触发**：构建史 / README 关键节点·全部战役 / 判定文档 / 预登记终稿
- **动作**：append-only；纠错只能**追加勘误块**，禁止 in-place 改写
- **校验**：脚本改写前必跑**原文存活核验**；净 diff 中的删除行必须逐条有对应保留

---

## ④ 行尾与量纲自证 ✅ 闸（EOL-GATE）

- **触发**：脚本批量改写任何文本
- **动作**：`io.open(..., newline='')` 读写，或直接 `rb/wb`；改完核 `CRLF` / `bare_LF` 与**父版本**一致
- **校验**：`git diff --stat` 若某文件变更行数 ≈ 该文件总行数 ⇒ **先怀疑行尾**，不得当内容大改提交
- **案例**：`ninfer_launcher.py`（LF）经 Python 文本模式写回变 CRLF ⇒ 整文件 3,504 行 diff

---

## ⑤ 记录三层（无闸）

- **触发**：出现「撤销 / 改判 / 新基线 / 环境分界 / 悬案收敛」任一种
- **动作**：README 关键节点 + 构建史 + commit body **三层同记**，缺一视为**未记录**

---

## ⑥ 提交信息纯净 ✅ 闸（T-COMMIT-MSG-GATE）

- **触发**：每次 commit
- **动作**：不含用户原话、不含日期、不含第一人称、无日记语气；subject ≤100 字，body ≤12 行

---

## 附：交付前 60 秒自查

```
1. 路径是从记录读来的吗？            （①）
2. 所有仓库 git status 都干净吗？    （②）
3. 动过历史文件吗？删了行吗？        （③）
4. 改过文本文件吗？核过行尾吗？      （④）
5. 有撤销/改判/新基线吗？三层记了吗？（⑤）
6. commit 里有日期/原话/第一人称吗？ （⑥）
```
