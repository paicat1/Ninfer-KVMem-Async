## 〇·定位：估计器是异步页流水的第二阶段（不是 KVMem 的补丁）

> **本节是全文档的前提**——不先讲清这层定位，后面 v0/v1 会被误读成"退回被动挤出"。

### 术语对齐：我们已做到的是"主动挤出"，"主动调取"还没做

| 动作 | 上游 KVMem | 我们（异步页流水） | 估计器之后 |
|---|---|---|---|
| **demote（挤出）** | **同步**：来一个挤一个老的，阻塞 decode 步 | **异步**：`PendingDemoteRing` 多批在飞，decode 不等 ⇒ **主动挤出** ✅ | 热度驱动：**挑着挤**（不是只挤最老的） |
| **restore（调取）** | 按需：本步缺哪页搬哪页，一次 wait | **仍按需**（patch 23 原文：`one batch wait`） | **预取：主动调取** ⬅ 这正是 v1 要补的 |

⇒ **我们已有的成绩 = 主动挤出**（demote 异步，+32.4%）；"**主动调取**"（restore 预取）**恰恰还没做**——它就是 v1。

### 三层结构：估计器解决谁的问题

```
上游 KVMem 的问题：无异步 ⇒ 每步同步等 ⇒ 均匀慢
    ↓ 我们解决（已兑现 +32.4%）
异步页流水：平均成本藏进 decode 步之间 ⇒ 但两件事没变：
    ① 挤谁   —— 继承上游 FIFO（按分配顺序，不看热度）
    ② 何时搬回 —— 继承上游按需（本步缺页才搬）
    ↓ 估计器解决
估计器：① 热度驱动（挑着挤）  ② 预取（主动调取）
```

**核心判断**：这两个次优在同步时代**被"均匀慢"掩盖**（那时每步都在等，早搬晚搬一个样）；异步之后平均成本被隐藏，**峰值 64 ms（2 步窗）反而成为唯一暴露面** ⇒ 估计器解决的是**异步页流水暴露出来的新瓶颈**，不是 KVMem 的老问题。

### 为什么这层定位重要（四条）

| # | 重要性 | 不写清的后果 |
|---|---|---|
| 1 | **防路线误读**：v0 调 depth、v1 管 preferred，表面像"被动挤出参数化"——**实际全程不动异步机制**，只给它更好的输入 | 后来者/评审会误判为"回退到同步" |
| 2 | **防收益混算**：异步 +32.4% 是**机制收益**（同步→异步）；估计器收益是**消峰收益**（平均→峰值） | 两者相加对外宣称 = 重复计数 |
| 3 | **定验证顺序**：v1 的价值主张（消 decode 峰值）**依赖 restore 分段结果**——若 64 ms 主要落在 prefill，主张须改为"削 TTFT 爆发" | 先跑错实验，再改口径 |
| 4 | **定发布口径**：对外材料现只说"异步页流水"（= 主动挤出）；估计器上线后须升级为**两段式**——"挤出异步化（已）+ 调取预取化（新）" | 笼统说"全异步"= 过度声明 |

### 一句话

> **异步页流水解决"怎么搬"（不阻塞），估计器解决"搬谁、何时搬"（不白搬、提前搬）。前者是机制，后者是策略；前者已兑现 +32.4%，后者目标是把唯一暴露面（64 ms 峰值）也消掉。估计器不是 KVMem 的补丁，是我们自己技术路线的第二阶段。**

### 设计边界声明（已知盲区，非疏漏）

**① PageHeat 的覆盖范围**：restore 的对象必然是"曾被 demote"的页（`Host-resident ⇒ 曾 device-resident ⇒ 曾被映射/读取`），故 PageHeat 对其**均有历史记录**。"冷页首次使用"走的是**分配**路径（fresh 写入 device，无 H2D），不在本信号职责内。

**② 真实盲区 = 衰减窗口 × 轮结构（轮长 + 轮间隔）**

| 场景 | 衰减状态 | v1 能否预取 |
|---|---|---|
| 同轮内热页保持 | 未过期 | ✅ |
| 跨轮前热页（轮长 + **轮间隔** < 窗口） | 未过期 | ✅ |
| **跨轮前热页（轮长 + 轮间隔 > 窗口）** | **归零** | ❌ |

**轮间隔是交互式 agent 的固有变量**（用户读输出、想下一步，几分钟到几十分钟，不可压缩）：轮长 30 s + 轮间隔 5 min ⇒ 单级 30 s 衰减下必然归零，**多级衰减也不能治**（三档都会被 5 min 的间隔穿透）。

**③ 修法：衰减时钟改"引擎活跃时钟"，且最佳实现 = 步计数（不是活跃墙钟）**

| 实现 | 慢态下的行为 | 轮间隔下的行为 | 字段成本 |
|---|---|---|---|
| 墙钟（现状设计） | 照走（步长变 6–7× 时窗口缩短） | 照走 ⇒ 热度归零 | 无 |
| 活跃墙钟（lummy 提法） | 照走（decode 在跑） | 暂停 ✅ | 需计时器 |
| **步计数（推荐）** | **按步走（与访问机会同步）** ✅ | **不推进 ⇒ 天然保留** ✅ | **零（`g_profile_step` 已有）** |

⇒ **衰减按 `g_profile_step` 推进**（每 N 步 `count >>= 1`）：慢态时步长变长不影响衰减速度（因为衰减的是"访问机会"不是"墙钟"），用户离开时步数不推进、热度天然保留。多级衰减（1 s / 30 s / 300 s 三档）**降级为可选的"活跃密度分档"**，不再是主修法。

**④ 决策层的已知次优点**：v1 用固定阈值（简单可预登记），未用自适应置换。升级条件：**固定阈值在深载↔浅载切换时误分类率超限 ⇒ 决策层切 2Q**（非一步 ARC——标准 ARC 需 ghost list B1/B2 + 自适应 p，超出 v1 的 ~50 行预算）。

**⑤ ARC-退化版后备（lummy 观察，记档）**：restore 事件本身就是"**被 demote 的页再次被访问**" = ARC 的 ghost hit 信号源现成 ⇒ 若 2Q 不足，"ARC-退化版"（用 restore 率直接调节 recency/frequency 权重）是下一步，**不需要完整 ghost list**。

## 四 v0：页操作率 → depth（价值小，可立即实现）

**输入**（全已有）：
- `demote profile: step=N ... demoted=M`
- `restore profile: step=N ... restored=K submitted=J`
- StepProfile：submit / wait / post / rest 四分解

**算法**：
```
r = (demoted + restored) / 步数
r > 阈值  ⇒ depth += 1
r < 阈值/2 连续 N 步 ⇒ depth -= 1
滞回：depth 变更后 50 步内不再变（防振荡）
```

**阈值怎么定**：从"**平均暴露 vs 步窗**"推——
```
平均暴露 ≈ (P/8 × 13.82 ms) / depth  < 32 ms
```
**不用 `depth ≥ P/4` 式**——那式把**峰值 64 ms 当成了均值**（单批 64 ms 是硬底，depth 压不掉）。

**目标函数**（路线图 §8.3 第 6 项前提 ①②）：
- 主目标：`tok/s 不降`
- **约束：P99 步时 ≤ 基线 × 1.2**（防 depth 一路加深、tok/s 好看但尾延迟崩）

**价值边界**：depth 只摊平均、不消峰；**对 TTFT 未测**（demote 97–99% 在 prefill，depth 可能影响 prefill 段并发）⇒ 降级表述是"对 decode/tok-s 收益小"，不是"depth 无用"。

## 五 v1：PageHeat → preferred + 预取（价值高）

**数据结构**：
```cpp
struct PageHeat { uint16_t last_step; uint8_t count; };  // 4 B/页
// 65536 页 × 4 B = 256 KB —— 纯内存，无 GPU
```

**衰减：按步计数（busy clock 的离散实现），不按墙钟**
- 每 N 步（如 32 步）：`count >>= 1`（或 ×7/8）
- 理由：衰减的对象是**访问机会**（每步一次 attention 映射），不是时间——
  - 慢态时步长变 6–7×，但"访问机会"不变 ⇒ 按步衰减与语义同步（按墙钟会误加速衰减）；
  - **轮间隔**（用户读输出，几分钟到几十分钟）内步不推进 ⇒ **热度天然保留**——这是墙钟与"活跃墙钟"都做不到的；
  - 字段零成本：`g_profile_step`（patch 23）已有。
- 多级衰减（1 s / 30 s / 300 s 三档）降级为可选的"活跃密度分档"，**非主修法**（见 §〇· 边界声明 ③）

**两个输出**：
1. `count > 0` ⇒ 进 `preferred`（别 demote）
2. 近期命中但当前不在 device ⇒ **提前 restore（预取）** ← **唯一能消 64 ms 峰值的手段**

**preferred 预算上限（防池被保护页挤爆）**：
```
保护上限 = mapped_pages − want_free − sink_pages − 安全余量
```
- 必须从 `want_free` 反推，**不用固定百分比**（浅载浪费、深载不够）
- 超限 ⇒ 降级为"允许 demote 但标记优先 restore"（与 `host_replica_current` 快速路径天然兼容）
- 否则第一次深载爆发就可能走 `ensure_ring_room` 的 early verdict 失败路径（:2695 bad_alloc）

**价值（两条，第二条由 lummy 补）**：

1. **消峰**：`restore` 峰值 64.01 ms ≈ 2 步窗，预取把尖峰整个挪出 decode 步；节奏器只能平滑不能消峰。
2. **thrashing 消除（免费，不依赖预测精度）**：热页进 `preferred` ⇒ 保持 residency ⇒ 掐断"demote → restore → demote"的页抖动。每次抖动 = 一轮 PCIe 往返（D2H + H2D）；深载下热页在两端反复横跳的隐形成本被 v1 直接消除——**保护本身即收益**，哪怕预取一行不写。

## 六 v2：置换算法（**不做闸**）

**真实价格**（lummy 增量 4 + CB 扩大）：代码 + **基准体系重建**（`baselines/`、`evidence/cases` golden sha、README 引用数字、两张冻结集、逐字门参考）+ **历史可比性归零**（等同换平台级别事件）。

**v1 vs v2 的分叉性质不同（lummy 精确化）**：

| | v1（preferred 保护） | v2（改选择序） |
|---|---|---|
| 语义分叉 | **条件性**：池宽裕时是**无操作**（输出不变），池紧张时才改"谁被挤" | **结构性**：每次 demote 都选不同页 |
| 分叉范围 | **有界**（只在池压力场景，可预期） | **无界**（所有 demote 场景，不可预期） |
| 基准影响 | 需要重立，但只影响池压力样本 | **全量重建** |

⇒ 语义冻结的紧迫性：v2 是全局性的，**没有语义冻结不能落地**；v1 可以先上线，但上线同时要重立受影响的 golden。

**"不做"主判据：preferred 预算触发率（lummy）**

```
v1 上线后统计 preferred 预算上限的触发率：
  < 10% 的步  ⇒ 保护够用，V2 永久搁置
  > 10% 的步  ⇒ 保护不足，V2 进候选
```

- **为什么用它作主判据**：预算超限 = 保护失效开始连锁（early verdict 失败 → 请求级失败）；它直接测"保护够不够"，而"峰值 + demote 页数"只测症状。
- **辅助判据（症状层）**：`restore` 峰值 < 1 步窗 **且** demote 页数不升。

**"新但冷"必须两分（lummy）**：

| 类别 | 定义 | 被挤的后果 | 算不算 V2 必要性证据 |
|---|---|---|---|
| **本轮冷** | 本轮没问，但**下轮可能回头引用** | 误伤 ⇒ 64 ms restore 找回 | **算**（误伤率才是真信号） |
| **永久冷** | 任务已切换（换问题域），真死页 | 挤了是纯收益 | 不算 |

- 判定钥匙 = **任务切换检测**；可行近似 = **prefix 变化**（引擎已有 `materialization_prefix_digests_`）：新请求 prefix 与旧不匹配 ⇒ 判任务切换 ⇒ 旧页归"永久冷"。

## 6b 语义冻结工程（V2 的硬前置，基础设施级）

**问题**：现行基准 = **sha 冻结**（golden sha 相等即等价）。它是**强判据**（sha 同 ⇒ 语义必同），但**任何页管理变化都会让它全量失效**——V2 必然触发，v1 部分触发，换平台已经触发过一次（§176 靠"GPU 未换"的运气绕开）。

**方案**：升级为**语义冻结**——判据用 PPL / 逐字门 / 确定性任务通过率，取代 sha 相等。适用范围远超 V2：换平台、换引擎版本、任何页管理策略变化。

**⚠ 必须先校准灵敏度（lummy flag，顺序不能反）**：

| 判据 | 强度 | 风险 |
|---|---|---|
| sha 相同 | **强**（⇒ 语义必同） | 无 |
| 语义判据通过 | **弱**（⇏ 无差异：PPL 差 0.1%、个别 token 漂移检不出） | **虚假安心**：真回归被漏判为"等价" |

**校准方法（现成标定集）**：**KV 精度档 A/B**（已知差异 = 开放式生成措辞不同，§177 实测 3/8 一致）——语义判据必须能**稳定检出**这个已知差异，才有资格用作冻结判据。

**顺序**：先校准（检出已知差异）→ 再启用（作为冻结判据）。反序 = 用未校准的尺子量所有东西。

**落地形态（待设计）**：
- **双轨**：sha 冻结（同配置、同 binary）+ 语义冻结（跨配置 / 跨版本 / 跨页策略）
- 每条 golden 记录"在哪一轨上有效"
- 跨轨比较必须显式声明（"这是语义等价，不是逐字等价"）
