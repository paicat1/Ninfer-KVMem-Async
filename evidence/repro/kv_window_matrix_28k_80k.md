# KV 窗口参数矩阵：28K → 80K 实测（2026-11-14）

## 条件

| 项 | 值 | 来源 |
|---|---|---|
| 引擎 | `engine-rc1-7e14453-6-g2755b24-dirty` | 日志 `build` 行 |
| 模型件 | `swift15_iq3s_mtp+dflash2.ninfer` | 日志 CMD 行 |
| `--spec` / `--draft-tokens` | dflash2 / 5 | 同上 |
| `--kv-capacity` | 81,920（1,280 页） | 日志 `capacity` 行 |
| `--prefill-chunk` | 512 | 同上 |
| 请求 | 单条 user message，不带 tools，`max_tokens=512`，`temperature=0.2` | `work/data/local-model-test/run_matrix.py` |
| 文档 | `gen_longdoc.py` 生成，哨兵在 5% / 50% / 95% | 同上 |

**不带 tools 是刻意的**：带 40 个工具定义时，`prompt` 里有约 13,500 token 是工具 schema（实测 48,262 字符文档：不带工具 28,650，带工具 42,116）。本轮测的是引擎窗口能力，与工具无关。

## 三个确定结论

### 一、`NINFER_TERNARY_KVMEM_SCORE_BUDGET` 的默认值 32768 是错的

默认 32768 → `budget_blocks = 32768/64 = 512` → 工作窗口 32,768 token。
42,276 的 prompt 下有 **149 个块（9,536 token）被丢弃**。
改为 65536 → 1024 块，**skip 全部归零**；改到 131072 → 2048 块，80,385 的 prompt 仍 skip=0。

**跨 28K–80K 共 6 次运行，skip 恒为 0。**

### 二、`NINFER_KV_RETRIEVE` 的默认值 8192 是错的

同一 prompt（52,162）、同一预算（1024 块），只改这一个变量：

| `NINFER_KV_RETRIEVE` | prefill | TTFT |
|---|---|---|
| 8192（默认） | 141.1 | 2m43.3s |
| 32768 | **230.1** | 2m39.2s |

**prefill +63%。** 默认值让每次 chunk 只能捞回 128 块，长 prompt 要捞很多轮。

### 三、`NINFER_KV_WINDOW` 必须 ≥ `SCORE_BUDGET`，否则预算被预留页数卡住

1024 块预算配 65536 窗口时，`window_tokens` 上限到 33,728 就不再增长（第 3 行 vs 第 2 行的 prefill 断崖：539 → 273）。
窗口放到 81920（等于池上限）后，`window_tokens` 一路跟到 80,384。

## 甜点与上限

| 区间 | prefill | TTFT | 判定 |
|---|---|---|---|
| **≤ 28K** | **539** | **53s** | **甜点** |
| 28K–34K | 273 | 2m3s | 可用，TTFT 翻倍 |
| 34K–52K | 230 | 2m40s | 可用，交互性变差 |
| 52K–64K | 261 | 4m6s | 勉强，适合离线任务 |
| > 64K | 131 | **10m13s** | **不可用** |

**尾段 prefill 序列显示退化机制**：每次运行的末尾几个 5 秒窗口，prefill 在 `153.4 / 76.8` 之间摆动——`76.8` 是 32K 窗口时代的"卡死值"，说明即使 skip=0，末段 chunk 仍走了最慢路径。

## 硬编码清单（需要修改的）

| 参数 | 现值 | 建议 | 依据 |
|---|---|---|---|
| `NINFER_TERNARY_KVMEM_SCORE_BUDGET` | 32768（默认） | **≥ 131072** | 42K 时丢 149 块；改后 80K 仍 skip=0 |
| `NINFER_KV_WINDOW` | 32768（默认） | **= 池上限** | 小于预算时 `window_tokens` 提前封顶 |
| `NINFER_KV_RETRIEVE` | 8192（默认） | **32768** | 52K 时 prefill 141 → 230 |
| `--kv-capacity` | 81920 | 80,385 已占 98%，**上不到 96K** | 第 7 行 |

## 边界

- 只测单条 user message、单问题、三哨兵位置固定；不外推到多轮、跨文档、长文档推理。
- 未测 `--kv-capacity` 之外的池档（96K / 122,880），也未测 `NINFER_KV_SINK` 与 `--prefill-chunk` 的影响。
- prefill 数值取日志 `req#N done` 行；尾段摆动来自 `throughput | 5.0s` 序列。
- 哨兵 3/3 只证明"该位置的内容能取回"，不证明长距离推理质量。
