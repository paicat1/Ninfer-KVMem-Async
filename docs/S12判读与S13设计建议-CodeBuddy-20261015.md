# S12 判读与 S13 设计建议（给家里线）

- 日期：2026-10-15 · 作者：CodeBuddy（办公室侧）· 事由：**S12 发生率对照 11 窗全部 VALLEY=0**
- 性质：**判读 + 下一轮实验设计建议**（不改变现有结论状态；供 S13 直接采用）

## 0. 一句话

**全 0 不是"PDL 出局"、不是"谷消失了"、也不是白跑——是第三次"没抓到题"。统计上它告诉我们：谷在 S12 的实验条件下不存在。差异不在 PDL，在实验条件本身。**

## 1. 统计读数（为什么这不是运气问题）

- 夜班成功夜（00:47-02:13）：**5 谷 / 85 分钟 ≈ 3.6 次/小时**
- S12（约 7.5 小时）：若率仍为 3.6/h，期望 ≈ 27 谷；**全 0 的概率 ≈ e⁻²⁷ ≈ 0**
- ⇒ "条件根本不同"是唯一自洽的解释。全 0 的真实价值：**排除"任何深负载都能诱发谷"这个假设**。

## 2. 与夜班的差异清单（嫌疑排序）

| # | 维度 | 夜班（5 谷） | S12（全 0） | 嫌疑 |
|---|---|---|---|---|
| 1 | **机器状态史** | 机器刚经历一整天重度使用（多次谷发作过、粘性态在场） | 凌晨 4.5h 空转 + 多次重启后起跑（"净态"） | ⭐⭐⭐ 最高 |
| 2 | **负载形状** | **每 9 循环换一种**（深 60K 单发 / 多轮 / 超池长解码 / 空转 轮换） | 持续单一形状（多轮增长 + 每三循环长解码） | ⭐⭐ |
| 3 | **窗口结构** | 老档一路长跑（谷现于 uptime 10-90 min 内） | **每 40 分钟重启** | ⭐（设计层不匹配，见下） |

**第 3 条的说明**：§14.2 刚以 3/3 验证"谷住在长跑引擎里、重启即重置"；而 §15.3 的 S12 采用"每窗起服"的短窗结构——**实际测到的是"起服后前 40 分钟的谷发生率"**。两者逻辑上尚未对齐：若谷需要更长的生长窗口，S12 在物理上就抓不到它（与 PDL 开或关无关）。

## 3. 三次实验的方法学复盘（全部败在"诱发性"）

| 实验 | 败因 | 类别 |
|---|---|---|
| 重启式 A-B-A | 重启即重置，被测状态被清掉 | 方法学缺陷 |
| 运行期 flag 切换 | 图捕获烘焙，运行期切不了 | 架构限制（已确证） |
| S12 发生率对照 | 条件不同，全 0 | **诱发性缺陷** |

⇒ **下一轮重心 = 诱发器，不是对照器。**

## 4. S13 设计建议（可直接采用）

**核心变更三件：长跑制 + 形状轮换 + 前置预热。**

1. **长跑制（对齐"谷住长跑"事实）**：
   - 组 A：PNF（不设 `NINFER_PDL_OFF`）起服 → **连续 3-4 小时**深负载 + 巡检，**组内不重启**；
   - 组 B：`NINFER_PDL_OFF=1` 起服 → 同负载 **3-4 小时**，组内不重启；
   - 组间切换时才重启（PDL 属性捕获期烘焙——这个限制长跑制天然适配：组内不需要切换）。
2. **形状轮换（对齐夜班成功条件）**：负载库恢复四形状轮换——
   - ① 空转×2 循环 → ② 深 60K 单发 → ③ 多轮增长跨池（60KB×8 ⇒ 15K→120K，含 longdecode 相）→ ④ 超池长解码
   - 每 9 循环轮换一次（参数对照夜班 `night_shift.ps1` 的触发矩阵）。
3. **前置预热（对齐机器状态史）**：每组开跑前，用**真实使用强度**（DSH 式多轮，或 a2gate 高负载）预热 1-2 小时——把机器"用脏"，再现夜班的状态史。
4. **判据**：组 A/B 的谷率 + 深谷次数对比（最少 2 组 ×2 轮）；若两组仍全 0 ⇒ **"机器状态史"假说权重拉满**，转第 5 条。
5. **降级方案（全 0 时的正解）**：放弃人工诱发，回到**守望者模式——真实使用中抓现行**（谷出现即用 S10 现场手段收证；注意运行期 PDL 切不了，现场只能做非 PDL 观测——**现场抓到的是"谷的形态与链定位"，不是"PDL 因果"**）。

## 5. 两个判读注意

2. **勿写"谷已消失"**——谷只是这 8 小时没进入那个状态；此前它消失后又回来过（三次自愈 + 两次来袭）。
