# 设计稿：挂账 46 I3b —— decode 步级仪表（Step Profile）

> 状态：设计（2026-10-13 夜）。施工未开。命名沿革：谷攻关 I1=谷内定位（现有仪表回读）→ I2=agentic 复现台 → **I3b=步级仪表最小可行版**。
> 纪律：**只观测、零行为变化**；只动 `engine-src/`（自持树）；不碰 .cu/内核；默认关、零开销门。

---

## 1. 目标

让**谷内每一秒 wall time 都有归属**（"每一秒都有名字"），把"静默自旋"拆成具名 host 段；随后才能按 tancau 条款进入定向修复：**先有诊断名，再下刀** ✗。

成功标准（先立后测）：
1. 谷现场下，单轮 decode 的 wall time **≥90% 有归属**；
2. 仪表**开/关零行为变化**（池内 greedy 逐字一致 + decode 中位不动）；
3. 门槛：谷形状（45–90K agentic）wall time **动出噪声**才算数。

---

## 2. 背景与证据链（为什么下一个仪表长这样）

**谷签名（跨 4 天观测集）**：decode 0.2–7 tok/s、host 94–148%、GPU 0–99% 两种情况并存；深谷 07:30–35 的 5 分钟桶：**mask=0 / SELECT=32 / retrieve=25 / ring profile=4（近乎静默）** ⇒ 成本在**未被任何现有仪表覆盖的"每步内脏"**。

**既有三层仪表已排除**（I1 结论）：
- ring 五段（sel/rr/mp/rs/mk/other）：深上下文仍亚毫秒~1.6ms、单次 max 32–40ms、STALL=0；
- demote：retire wait≈0、batch copy 0.35–5.7ms；
- MTP：接受率 55–82% 全程正常。

**今晚新证据（2026-10-13）**：
- **谷=时间现象**：`--mtp-attention-window` ON 臂 r2 首触撞 199.3s 停顿，输出与 42.8s 的 OFF 臂**逐字相同**（sha `38cfbb97`）⇒ 谷吃的是**轮次/时间**，不坏 token；
- **超池 residency-态依赖**（挂账候选）：同输入、不同缓存态 → 不同输出（OFF 臂自身 run2/run3 亦不同）——与谷**同一矿区**，仪表应顺带观测。

**外部参照（只读）**：tancau `decode-host-attribution-plan`（结构同型：Stage 0 验 host_work→Stage 1 每相计时→Stage 2 点名后动刀）；其定案"**host 税 = 限轮器**"（350ms/轮→2.9 轮/s→8 tok/s；修后 91ms/轮→11 轮/s→30 tok/s）——我们的谷极可能是同一类"每步 host 段膨胀" ✗。

**自有路径知识（已核/待核）**：
- `engine_core.h`：`decode_round` 计数（**步边界标记**，已核）；
- `context.cpp` ~3019：`install_resident_selection`（commit 点，已核）；~1981：`RingProfileWindow`（**可复用的窗口结构**，已核）；~1850：`demote_other_addresses_to_host`（已核）；
- mask 安装 `hidden=0` 时**静默不打印**（已核，现无任何仪表覆盖）。

## 3. 设计：五段 + 双侧时间戳 + 输出格式

### 3.1 第一版（最小可行）五段

| # | 段 | 含义 | 打点锚 | 状态 |
|---|---|---|---|---|
| S1 | `submit` | 一轮 decode 的 program_submit 全段（现 ring profile 的 `other` 无归属处） | submit 入口/出口 | **待读码定位** |
| S2 | `setup` | 每轮 graph/rows 准备（tancau：setup 130→189ms/轮增长、rows 独吞） | 同区 | **待读码定位** |
| S3 | `mask` | mask 安装路径（hidden=0 静默分支——现全盲） | `install_resident_selection` 邻域（~3019） | 锚已核 |
| S4 | `ensure` | 每步 KV ensure/restore 检查（tancau 3.2× 修复点同族） | `ensure_*` 家族函数 | **待读码定位** |
| S5 | `post/sync` | 提交后记账 + kernel 同步等待 | `decode_round` 记账邻域（已核） | 锚已核 |

### 3.2 双侧时间戳（硬要求）

每段同时记 **submission 侧**与 **completion 侧**时间戳——把"干活慢"与"等 GPU 背压"分开（tancau 教训原文：GPU idle + CPU busy = host slowness，两者不得再混同）✗。

### 3.3 输出格式（并入既有行，不新增文件/事件）

```
[ninfer] step profile window: steps=512 avg ms submit=… setup=… mask=… ensure=… post=… | max ms … | q wait=…
```
- 窗口机制**复用 `RingProfileWindow`**（窗宽 256–512 步），打印挂在现有 `[ninfer]` 输出点；
- 队列侧：queue admission/等待进同一记录（我们的 queue 24–290ms，与谷关系未知）。
