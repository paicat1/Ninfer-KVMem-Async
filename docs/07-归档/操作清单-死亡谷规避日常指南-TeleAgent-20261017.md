# 操作清单：死亡谷规避日常指南（初稿 v2）

- 拟稿：TeleAgent · 2026-10-17 · 状态：**初稿 v3（v2 按用户批注修订；v3 补复现率轮结论与深谷粘性，2026-10-17 21:5x）**
- 依据：2026-10-17 全部实验结论（E-C / E-D / E-E / ctx / 复现率轮 150×5+400×3 + 自然谷 437）
- 一句话：谷 = **状态依赖 × 概率性**的"解码变慢"现象（不崩溃、不丢请求）；**规避不依赖根因闭合**

---

## 一、死亡谷的表现现象

**体征表**（谷发生时的典型数字）：

| 指标 | 健康 | 谷中 |
|---|---|---|
| 解码速度 | 150–170 tok/s | 2–35 tok/s（硬压档 0.2–2） |
| GPU 功耗 | 250–290 W | **70–86 W（腰斩）** |
| GPU util | ~99% | 100% |
| host/round | ~27 ms | 0.28–3.7 s（历史峰值 24.5 s） |
| device_wait | 350–540 µs | **不变**（不是设备问题） |
| 引擎搬页 | 0 | **0**（d2h/h2d/spill/evict 全 0） |
| 引擎状态 | 正常 | **正常**（降速但继续产出、请求不丢） |

**观察到谷的条件**：
- **长解码 + 外部显存占用较高** 同时出现（短问答/短探针从未观察到）；
- 人工加压（vram_hold 100–400 MiB）可诱发（**7 次加压 6 次致谷**）；
- 持续时长：几秒到 29 分钟（自然谷 437）；**浅谷释放/请求结束即消**；**深谷有粘性**——释放后残留 0.19–1.1 s（半恢复），完全恢复约 1–3 分钟（或请求结束）；
- 深度形态（剂量决定）：150 MiB → 浅谷（~0.8 s/round，仍出 token）；400 MiB → 深谷至**"停顿"**（1.0–1.4 s，可零 token）。

**一句话辨认**：`nvidia-smi` 里 **util ≈100% 但功耗 <100 W** = 疑似谷。

## 二、已开展的排查与排除项

| 排查项 | 方法 | 结论 |
|---|---|---|
| 等设备 | device_wait 全程监测 | **排除**（350–540 µs 不变） |
| 引擎搬页 | 引擎计数器 d2h/h2d/spill/evict | **排除**（全 0） |
| 显存不足/OOM | 分配失败检查 | **排除**（零 OOM） |
| CPU 竞争 | vram_hold 零 CPU（sleep_for） | **排除** |
| 主机内存 | 充裕 | **排除** |
| 准入/统计异常 | 全 0 | **排除** |
| 第二 CUDA 上下文 | 1 MiB×2 实验 | **排除**（两拍全健康；机器本就 ~10 个 CUDA 进程） |
| 请求形态单独作用 | 无压 437 形态 / 90k 深超池 | **排除**（无压全健康） |
| "空闲显存数值"作判据 | 多点对照 | **证伪**（167 谷 / 179 健康 / 265 谷 / 305 谷 / 328 健康——非单调） |
| 池大小 | 65536 → 51200 → 49152 | **深度因子**（谷深单调递减但不为零） |

**已定位（未闭合）**：病灶在 **host 侧 `program_submit`**（26 ms → 2.5 s，93×）；**为什么**被拖慢未闭合（ETW 待做）；**触发为概率性，已量化（复现率轮 8 拍）**：外部压力 **150 MiB ≈ 1/5（20%）**、**400 MiB = 3/3（n=3，存在性证据；未见反例，但样本量小——不作"必中"普遍断言）**——"边界"是**概率曲线**（概率与深度均随剂量上升）；时变因素未量化。

## 三、已验证的缓解手段与原因

| # | 手段 | 证据 | 原因 | 限制 |
|---|---|---|---|---|
| 1 | **降低外部显存占用**（关非必要程序） | 剂量-概率正相关（7 次加压 6 次致谷） | 外压是触发因子 | 地板关不到 0；不保证 100% |
| 2 | **池折中（49152）** | 谷深 2.4–3.7 s → 0.28–0.37 s（约 8× 减浅） | 推断：池占用减少 → 系统级余量增加 → 谷深减轻（待机理层闭合） | KV 驻留减少；不消除谷 |
| 3 | **谷中释放外部压力**（救场） | 释放 → 恢复（93× / 18× / 14× 反转）；**深谷释放后有残留**（0.19–1.1 s） | 触发条件移除 → 状态消退 | **深谷非即时**：完全恢复 ~1–3 分钟或请求结束；真实程序场景待实测 |
| 4 | **重启引擎**（兜底） | E-C/E-D 重启后恢复健康 | 清零进程状态 | 不免疫（重启后仍可能谷）；服务中断 |
| 5 | **等待** | 437 自然谷自行完成；实验后 ~2–3 分钟自愈 | 谷随请求结束消失（437 实证：请求结束瞬间状态即消） | 可能很久（29 分钟） |
| 6 | 监控留证（值守工具） | 全天候工作 | 自动发现 + 立案 | 事后性（见 §八） |

## 四、L1 预防（跑长任务前，约 1 分钟）

```powershell
nvidia-smi --query-compute-apps=pid,process_name,used_gpu_memory --format=csv   # 谁在占显存
nvidia-smi --query-gpu=utilization.gpu,power.draw,memory.free --format=csv     # 总况
```

- 关掉：浏览器 / WebView / Overlay / 其它推理进程等（**能关的都关**）；系统桌面进程（数百 MB）属正常地板，不用管；
- 原理：**少占一点，概率低一分（不保证）**。

## 五、L2 事中：救场流程（分步）

**Step 1 — 确认是谷**（任一条）：
- 解码明显变慢（长输出时体感）；
- 功耗指纹：util ≈100% 且 **功耗 <100 W**；
- logwatch 立案（如开启，见 §八）。

**Step 2 — 列出持有者**：
```powershell
nvidia-smi --query-compute-apps=pid,process_name,used_gpu_memory --format=csv
```

**Step 3 — 按优先级关闭**（从高到低）：
1. **其它推理 / CUDA 进程**（同性质持有，优先级最高）；
2. **浏览器 / WebView**（msedgewebview2 等）；
3. **Overlay**（NVIDIA Overlay 等）；
4. 系统进程不动（dwm 等——关了也白关）。

**Step 4 — 观察恢复**（30–60 秒内）：
- **功耗回升到 250 W+** = 已回血；
- 解码速度回升（150+ tok/s）确认。

**Step 5 — 若 60 秒未恢复**：升级到 L3（§六）。

## 六、L3 兜底

- **等**：谷中引擎仍在跑（13–35 tok/s），不赶时间可等（437 自然谷自行完成）；
- **重启**：深谷持续（host/round >1 s 级）→ 重启引擎（**走可见窗口规范入口**）——中断当前谷（≠免疫）；
- 证据自动留档（如开启值守，见 §八）。

## 八、值守工具（可选章节）

> 这些是"观察者"，不影响引擎行为；正常使用可不管，出问题时案卷可查（`evidence\cases\`）。

| 工具 | 作用 | 触发 |
|---|---|---|
| logwatch（日志通道） | 引擎日志谷信号检测 + 自动立案留证 | 自动 |
| 猎人 | 每分钟轻探针（decode<60 候选 + 守卫） | 自动 |
| 看门狗 | 监控其它工具存活并告警 | 自动 |
| 采样器 | 背景时间线采样 | 自动 |

- 开启/关闭由值守体系（可见窗口）管理；**非必需**——最小使用场景（§四–§七）不依赖它们。

## 九、诚实声明

- 规避**不保证 100%**（边界是概率曲线；机理未闭合）；
- 概率标定（8 拍）：150 MiB ≈ 20% / 400 MiB = 100%（时变因素未量化）；**深谷释放后有粘性**（1–3 分钟）；
- 数字基于 2026-10-17 认知——认知更新后本清单需修订；
- "外压 <100 MiB 安全"**不可作保证**；"**越少越好**"是唯一稳的方向。
