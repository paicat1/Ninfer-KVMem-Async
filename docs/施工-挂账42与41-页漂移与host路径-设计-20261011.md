## 0. 目标与非目标

**目标**：
- G1：超池会话（prompt ≫ 池）的 **decode 速度恢复到与池内同量级**（实测病灶：122K 会话 decode 2.6-12 tok/s，host 98-110%；池内基线 100-134 tok/s）；
- G2：**压缩/断档后的 sequence 重建不再风暴**（实测病灶：cache 0% 后 prefill 49.9（25 倍慢）、TTFT 3m32s，host 498%）；
- G3：**客户端停止读/断开不再挂死引擎**（挂账 41：请求永占并发槽）。

**非目标**：
- 不做"会话深度 > 池时的零召回"（`silently unreadable` 是 B28 既定口径，检索边界问题另案）；
- 不做多并发（KVMem 环硬约束不变）；
- 不改 KV dtype / 池容量语义。

## 1. 病灶（全部 file:line 实证）

### 病灶 P1 · restore 逐页同步 + restore/demote 同池抖动
`context.cpp:1614-1648` `restore_kv_pages_from_host`：**逐页循环**，每页独立
`make_empty_reservation() → resize_reservation(1) → restore_page_from_host(..., device.stream)`
——每页 2 MiB 单拷贝 + 单页 reservation 开销，无 run 合并、无多 stream、无预取；
L1637 `free_runs().empty() → break`：restore 受 free 页限制 → 空页不足触发 demote（`demote_kv_pages_to_host`，64 页/批，L1842-1914）
→ **restore 要的页挤出别的页 → 下一步再 restore 回来 = 颠簸**。实测：122K 会话 span 1,946 页 vs 池 1,024，host 98-110% 持续。

### 病灶 P2 · scoring 每 decode 步全量重打（**第 0 步已落档：部分证伪 + 真凶改判**）
`context.cpp:2488-2493`：仅当 `mapped_now != sequence.ring_scored_mapped` 才重打分；
**decode 每步 mapped 都 +1 → 每步都调 `select_retrieval_pages`（全量）——调用频率证实**。
**第 0 步读码结论（2026-10-11，源码级）**：
- 打分**不读 KV 页内容**：content 路径查 ops 预计算分数表（`kvmem_score_selected_blocks`，
  prefill 期已算好）；lexical fallback 遍历 **sequence.ledger 的 token ids**（host 内存，
  `context.cpp:1709-1713` 注释自证 "needs no Device work"）——**"每步读 931 页 KV 内容"的假设证伪**；
- 真凶改判 = **tancau brief §10.14 记录的同款 "host 税"**：他们同样实测 decode 8 tok/s
  （GPU ~0%、host 每轮 350ms），修后 91ms/轮 → 30 tok/s——**"把轮次放开"而非提速 GPU**；
  本线 decode 3 tok/s + host 98-110% = 每步的页操作（P1 抖动 + P3 重建 + mask 安装 CPU 遍历）
  组成的 host 税，机理同族、幅度更重（超池深度更大）；
- **M2 降级为低优先**（ledger 遍历是 CPU 成本，非 KV 带宽；每步 1,946 页遍历仍可增量化，
  但不是 3 tok/s 的主因）——主力修法改 P1/M3（restore 批量 + 抖动协调）。
**tancau 量化参照（brief 实测）**：host 税 350→91ms/轮；工作集 ≈ 池的 23.8%（640 页/2,688 页）；
每 chunk 工作区成本 198 KB；抖动次数 = 总 token/chunk（173K@1024 = 169 次）；
"抖动减少 N 倍 ≠ 重算减少 N 倍，减掉的只是每次调用的固定开销"（M1 预期管理）。

### 病灶 P3 · 压缩/断档后的 sequence 重建无流水
cache 0% 时（实测 req#50）：老 sequence 的 ~1,946 页要清理/重映射，新 sequence 逐 token 等页操作
（prefill 49.9、TTFT 3m32s、host 498% 多线程爆炸）——与 P1 同根（页操作同步、无批量）。

### 病灶 P4 · 客户端停读/断开 → 引擎挂死（挂账 41）
decode 线程阻塞在同步 socket 写（无 send timeout）；断开后请求不取消（永占并发槽）。
判据签名：CPU delta=0 / GPU idle / TCP Established / 日志静默（`test_stream_stall.py` 可复现）。

### 上游参照（已对齐）

## 2. 修法（M1-M5，按依赖排序）

### M1 · restore 批量化（治 P1 的拷贝效率）
`restore_kv_pages_from_host`：
1. 入参 logical_pages 先排序并合并为**连续 run**（extent 连续段）；
2. 每 run 一次 `resize_reservation(run_len)` + 一次 `restore_page_from_host`（或等价批量 H2D）；
3. 保留逐页 fallback（run 拆分失败时回退现路径）。
预期：931 次小操作 → ~10 次 run 拷贝；拷贝总量不变，开销项（reservation/锁/launch）÷93。

### M2 · scoring 增量化（治 P2，第 0 步证实后开工）
- host 页**不参与逐 decode 步打分**（分数缓存 + 仅在页状态变化时重打）；
- 或 decode 步打分只覆盖 `sink + evidence + recent`（resident 集），host 页仅在
  prefill/轮界评分（低频）。
判据：decode 期 host 占用从 98-110% 回落到 <20%；decode 恢复 ≥90 tok/s。

### M3 · restore/demote 协调（治 P1 的抖动）
1. **restore 集与 demote 集不相交**：demote 候选排除"本步 attention 实际选中的页"
   （mask 已知——`install_resident_selection` 的 resident 集）；
2. **demote 只从"非本轮 mask、非 sink、非 evidence"的页里选**（现 FIFO 从 sink 后顺扫——
   改为跳过本轮 mask 页）；
3. restore 配额 = `free + demote 配额`，一次规划（先 demote 后 restore 的两阶段，避免中途互抢）。
判据：连续 100 步 decode 的 restore/demote 页数比从 ~1:1 降到 <0.05。

### M4 · stale-error 清理 + 断开取消 + prefill 心跳（治 P4，挂账 41）——**独立先行，无依赖**
1. 所有"捕获失败但继续"的分支（对照 issue #114 的 skipped 形态）在 skip 后调用
   `cudaGetLastError()` 清 stale 状态——**全树扫描 `CUDA_CHECK` 前的 skip 路径**（TELE 审核 §二意见 1）；
2. socket 写改**可中断**：写前检查 client 断开标志（或 `SO_SNDTIMEO`）；
   断开 → 取消该请求 → 释放槽位 → 日志一行（判据：`test_stream_stall.py` 关闭后
   引擎 5 秒内恢复 running 0）；**复现时留档冻结期日志**（TELE §一 §3 备注）；
3. **prefill/长思考期间发 SSE 心跳**（上游 tancau brief §9.4 同款建议：
   DSH `dsh-llm-pi-ai:1896` stream idle timeout 300s——prefill 6-12 分钟静默必然触发；
   本线已由 `streamIdleTimeoutMs: 3600000` 客户端侧规避，引擎心跳是服务端侧根治）；
4. `fail_all_locked` 类路径已有日志（Bonsai 已修），复查本线无回退。

### M5 · sequence 重建批量化（治 P3，依赖 M1/M3）
cache 断档时：老 sequence 页清理改为**批量两阶段**（先标脏/批量 D2H，后批量释放），
与新 sequence 的页分配解耦（不再逐 token 等页）。
判据：压缩后首轮 prefill 从 49.9 → ≥1k tok/s；TTFT 3m32s → <30s。
