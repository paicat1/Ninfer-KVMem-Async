## 〇、研究背景与三个前提

对"本批 0-8 是否构成对谷承诺的反例"做开放研究：不先入为主判定真伪，而是把问题上升为"诊断体系公信力审计"。

**前提 1（谷承诺为真）**：谷是实测且可验证的现象，承诺数据真实。注意：此处"谷"=承诺里被验证过的谷，非本批出现的"慢态"。

**前提 2（阈值/基线可靠）**：诊断依赖的阈值与基线（如 400MB 自由显存边界、decode<60 判谷等）是可靠、相互自洽的基准。

**前提 3（诊断体系自洽）**：诊断体系（前提、方法、证据）内部一致、无自我矛盾。推论：若体系自洽，则"真实承诺（应触发）"应当触发体系的告警。

## 一、核心框架：元审计（测量失败 vs 承诺失败）

本批核心逻辑必须用"四层结构"厘清，这是整个审计的骨架：

```
承诺层    : A → B
            A = 触发条件（外压 ≥400MiB 且 自由显存 <400MB，AND）
            B = 谷出现（探针口径 decode<60，低功耗，host 停摆指纹）

测量层    : 测 A（剂量/free）→ 测 B（decode/基线）
            A 是否满足、B 是否出现，都依赖测量

元审计层  : 判定"0-8 是测 A 失败 还是 测 B 失败"
            测 A 失败（free 未贴边）→ 0-8 属测量失败，承诺未被打
            测 B 失败（A 满足但 B 未现）→ 0-8 属承诺失败

自证层    : 判定"测 A 失败"依赖 free 测量，
            free 测量又依赖 nvidia-smi 口径 / 引擎状态 / 工具
            → 更深一层"同一性/自证"冲突（见漏洞 3）
```

**本批裁决**：free=538 MiB > 400MB ⇒ A 未满足 ⇒ **0-8 属"测量失败"，非"承诺失败"**。这句话的正确性是本审计的落点，但它引出的"如何程序化判定测 A 失败"才是真正要修的（见 §六）。

## 二、Q1：0-8 与"400MiB 3/3"的关系（可重估，非证实/证伪）

**回答**：0-8 **既不证伪、也不证实**承诺 3-3；但可以**重估承诺的表述与适用域**。

推演（TELE 独立）：
1. 承诺 A→B 是**条件句**。测 0-8 时 A 未满足（free 未贴边），故 B 不出现**不违反承诺**。
2. 但承诺的"验证完整性"：要验证 A→B，必须在 **A 满足** 时测 B。若从未测过 A 满足的情况，则承诺"从未被真实验证"。
3. 历史 3-3 是在**池 49152 + 400MiB + 探针口径 + free 234–491 贴边**下测的——那是"测 A 成立时的 B"，且 3-3。故承诺在**该特定配置下被验证过**。
4. 本批（池 65536 + 长请求 + Gen4）不在 A 的成立域内 → 0-8 **不构成对承诺的验证**（既非证实也非证伪）。
5. **重估价值**：0-8 逼出了"承诺适用域从未被精确枚举"这一漏洞（§四），迫使把承诺从"普遍断言"改写为"域内断言"。

**关键结论**：0-8 的价值不在"结果"，而在"它暴露了承诺表述的边界缺陷"。

## 三、Q2：诊断体系阈值/基线可靠性清单（哪些实际依赖判"本批无谷"）

判定"本批无谷"**实际依赖**的判据，逐一列出并评估可靠性（这是 Q2 的回答：我们其实依赖了不止一个阈值，且多数是单点、未标定置信）：

| # | 判据/基线 | 出处 | 可靠性评估 | 判"无谷"依赖度 |
|---|-----------|------|-----------|----------------|
| 1 | 探针 decode <60 判谷 | skill §4 判据 v4.1 | 单测，未标置信区间；**口径为 a2gate 探针，本批未用探针** | 高（间接：用 50.6-87.3 对比隐含调用） |
| 2 | host 停摆指纹（host/round 1.90-3.67s + 低功耗 + 满频） | 工程史 L45/L47 | 历史值，非本次实测 | 高（判"形态不同"） |
| 3 | 触发条件 AND（外压≥400 + 自由<400） | 构建史 L3212 | 本批 free=538 不贴边 | 高（判"测 A 失败"） |
| 4 | 400MiB 3/3、150MiB 1/5 承诺 | 工程史 L111 | 历史 n=3/5 偏小；探针口径 | 中（承诺真实性的前提） |
| 5 | 池大小（本批 65536 vs 历史 49152） | 构建史 | 本批显式 | 中（解释 free 差异） |
| 6 | 自由显存边界 400MB | 构建史 L3212 | nvidia-smi 实测 538 | 高（核心） |

**Q2 回答**：判"本批无谷"**主要依赖 #1、#2、#3**。其中 **#1 是最大隐患**——本批根本没跑探针口径，用"长请求 50.6-87.3"与 60 对比，**是混口径比较**（探针 155 快 vs 长请求天然更低）。#3 的 free=538 是**推算**（总量 16303 − used 15765），**不是 memory.free 直采**——这是个独立瑕疵（见 §五、漏洞补充）。

**结论**：判"无谷"依赖的阈值**可靠性参差**，最大隐患是**口径错位（#1）**与**free 推算（#3）**。这两点不修，"无谷"结论的可信度打折。

## 四、Q3：承诺可复现性依赖的假设（漏洞 1 + 漏洞 2）

"我的承诺可被复现"这句话，**实际依赖的假设清单**：

**假设 1（适用域不变量）**：承诺适用的"配置域"是恒定的。
- **假**：池大小、口径、采样、环境都会变。承诺未声明适用域，即默认"任意 400MiB 都应触发"，**但这是过度断言**。

**假设 2（存在性 = 普遍性）**：
- 3/3 是**存在性证据**（存在某配置下 400 触发 3 次）。
- 承诺写成 **普遍性**（"400 必触发"）。
- **这是承诺强度错位**：用存在性证据支撑普遍性断言，**承诺比证据强**。

**假设 3（复现依赖条件不变）**：
- 复现依赖的 nvidia-smi 口径、引擎状态、环境变量被认为不变——但实际会变（IDLE 漂移、Gen4、采样）。

**Q3 回答**：可复现性依赖三个假设，**假设 1、2 在架构层面成立但不满足**（适用域未声明、存在性被当成普遍性）。**复现性论证的可靠性 = 弱**，因为它依赖了一个未声明、未验证的域。

**修法（CB 补充，吸收）**：
- 承诺必须 5 元组声明适用域：**池、口径、量化、采样、样本数**。
- **声明本身也必须是被测的**——新配置域未测过，就不能叫"承诺"，只能叫"推测"。
- 承诺表述精确为"**在域内，存在剂量 → 触发**"，严禁写"400 必触发"。

## 五、Q4：多对多、互斥关系的解释 + 自证/同一性冲突（漏洞 3）

### 5.1 为什么"承诺真 + 诊断自洽"还会出现 0-8？

回答：**因为 0-8 根本不落在"承诺×诊断"的交集中**。

- 承诺的检验域 = A 满足（free 贴边）的配置。
- 本批 A 未满足（free 未贴边）→ 本批**在检验域外**。
- "承诺真 + 诊断自洽"只要求：**在检验域内，承诺应触发告警**。域外 0-8 不构成对"承诺×诊断"的任何反例。
- 故"多对多互斥"悖论**不解自解**——两者都是"好的"，但本批不在它们约束的坐标内，无冲突。

### 5.2 但这里暴露**真正的自证/同一性冲突（漏洞 3）**

CB 的纠正（吸收，更准确）：
- **不是"自由显存测量 是 自证"**，而是：
  - ① **测量本身是"可信度问题"**——free 必须**他证**（nvidia-smi 直采、引擎日志、独立工具三方对）。
  - ② **判别"测 A 失败"不须自证**——"本批域外"这一事实可独立于承诺得出，不需承诺自证。
  - ③ **真自证在更深处**：被测量的" A（free 贴边）"与判断" B（谷）"的**判据同源**（同一观测系统、同一 nvidia-smi、同一引擎日志）。A 的定义与 B 的判据是**同一系统的两个读数**，存在**同一性冲突**——测量 A 的工具（nvidia-smi）正是测量 B 依据的一部分工具链。这层不剥离，审计就有"自己判自己"的死角。

### 5.3 触发条件必须是"实测的 free"，不是"推算的 free"

CB 指出（吸收，关键）：
- **free=538 是"总量 16303 − 施压期 used 15765"推算**，不是 free 直采。
- 但触发条件的成立（free<400）必须是**实测压测值**，不能用推算值冒充。
- 推算 → 可能掩盖：引擎内 KV 占用波动、WDDM 不即时归还、其他进程抢占——都会让"推算 free"失真。
- **结论**：free 的"成立判定"必须用实测直采（且三方他证），" 推算"只能作旁证。

## 六、测量失败 vs 承诺失败的程序化判据（可复判）

判定"0-8 是测失败还是承失败"**必须程序化**，不能凭一次性判决定死。程序判据（多写进文档，供复现判）：

```
给定一批 0-8（施压了 M 次、每期 free 已录、每期 B 判据已录）：

① 检查本批是否真正测到 A：
   - free 全程均 >400MB（或任一时刻未贴边）？
      是 → 测量失败（未测 A），承诺未破，批作废补测。
      否 → 进入 ②

② 是否曾测到 A 满足（free <400MB 至少一拍）？
   是 → 进入 ③（A 曾成立）
   否 → 测量失败（A 从未测到），承诺未破。

③ A 曾成立时 B 是否出现？
      出现 → 承诺成立（且 B 观测到）。
      未现 → 承诺失败（在域内 0-8 = 真失败）。
```

**核心规则**：
- **域内 0-8 = 承诺失败**（真反例）。
- **域外 0-8 = 测量失败**（不是反例）。
- **"测 A 是否成立"必须实测，不得推算。**

这一程序判据是公信力审计的核心可复现产物——它让"0-8 是不是反例"从"一次法官判决"变为"可重算的程序"。

## 八、结论与建议（中性落点）

1. **0-8 = 测量失败（free 未贴边），非承诺失败** —— 定论，不夸大不淡化。
2. **承诺存在两个真实缺陷**：适用域未声明（漏洞 1）、存在性证据被写成普遍性断言（漏洞 2）。
3. **诊断存在一个真隐患**：free 用推算而非实测（触发条件判定未实证）+ 判定依赖口径未统一的 decode（#1）。
4. **自证/同一性冲突（漏洞 3）**：A（free）与 B（谷判据）观测同源，须以独立工具他证剥离。
5. **下一步（供用户裁决）**：
   - 修承诺表述（5 元组域 + 域内句），写入公开材料合规区；
   - 复测采用实测 free（nvidia-smi 直采 + 三方他证）+ 探针口径 + 记录 clk/pow；
   - 固化"测量失败 vs 承诺失败"程序判据到复测文档，供可复判。
