# 预登记：A2 —— "两阶段爬升"到底随哪个变量累积（2026-10-18）

## 背景（为什么做）

机理已钉到 `cudaGraphLaunch` 阻塞（25 ms → 497 ms 中位 / 2.23 s 最大）。唯一可指着往下挖的硬线索是
**阻塞两阶段爬升**（26 → ~550 → ~2,050 ms，约 100 s 爬满）⇒ 说明有东西在累积。
本轮目的：切开"累积的到底是什么"。

## TELE 指出的原设计两处错位（已采纳修正）

1. **原设计"只改 max_tokens"测不到上下文** —— prompt 不变 ⇒ 上下文 KV 页全程一样，
   差异只能归因于"输出长度"，切不开"上下文 KV 页"。⇒ **必须变 prompt 长度**。
2. **短请求持续不足** —— 爬升窗 ~100 s，短请求 20–30 s 就结束 ⇒ 观察不到第二阶段 ⇒ 假阴性。
   ⇒ **必须固定长输出保证时长 ≥180 s**。

## 设计（单变量）

| 项 | 设定 |
|---|---|
| **自变量** | **prompt 长度**：短（~200–500 tok） vs 长（8,848 tok，437 形态） |
| 固定 | 输出 24,000（保证持续 ≥180 s）· 外压 **400 MiB** · **池 49152 不变** |
| 样本 | 短/长各 **≥2 拍**（爬升窗内至少 2 个采样点） |
| 入口 | 经 `spawn_visible.ps1`（可见窗口）· 全程走规范入口 |

## 判据（预登记，不得事后改）

| 结果 | 结论 | 下一步 B 该抓什么 |
|---|---|---|
| **短 prompt 仍两阶段爬升到 ~2 s** | 与上下文 KV 无关 ⇒ **驱动侧状态累积** | B 盯驱动内部（页表/VA/图提交序列化） |
| **短 prompt 不爬升（停在 ~0.5 s）** | 与上下文相关 ⇒ **主机 KV 回搬路径** | B 盯 KV 回搬/页就绪 |
| 两者都爬但幅度不同 | 两者皆参与，按幅度定权重 | 分别量化 |
