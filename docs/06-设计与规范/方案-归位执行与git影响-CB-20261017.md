## 三、安全协议（每批必须走完，缺一不做）

1. **前置**：`git status` 必须**干净**、`未推 = 0`（否则先收尾）；
2. **清单**：出"源→目标 + 是否跟踪 + sha256 + 体量"清单（写入 `work/<date>/relocate_<batch>.md`）；
3. **备份**：**未跟踪件**先复制到 `_safety_backups/<date>/`（跟踪件不必 —— git 就是备份）；
4. **活件判定**：三源（运行进程映像 / 登记册 / 最近写入 <300 s）任一命中 ⇒ **本批跳过该项**；
5. **忽略复核**：目标目录若被忽略（`git check-ignore`）⇒ **只允许移动未跟踪件**；
6. **执行**：跟踪件用 **`git mv`**（保历史）；未跟踪件用 move；**先改引用或同时改**；
7. **验证**：`scripts/gates.ps1`（引用 + 结构）必须 **rc=0**；`git diff --stat` 复核**应只见 rename/删除**，不得出现整文件重写；
8. **提交**：**一批一个提交**（便于 revert）；提交信息写明"批号 + 件数 + 引用改动"；
9. **登记**：退役件写 `retired/INDEX.md`；转正件在报告里留指针。

## 四、回滚

| 情形 | 回滚方式 |
|---|---|
| 跟踪件移错 | `git revert <该批提交>` 或 `git reset --hard <前一个提交>`（**未推**时） |
| 未跟踪件移错 | 按清单反向移动（清单含 sha256 可校验完整性） |
| 误删（已提交） | `git checkout <前一个提交> -- <路径>` |
| 误删（未提交） | **回收站**（删除走回收站）+ `_safety_backups/` |
| 引擎件 | `hash_cache.json`（sha）+ `engine/lineage/`（同 sha 副本） |

## 五、我的执行建议（安全优先）

1. **先做"零 git 影响"的三批**（P1a/P1b/P3/P5/P7）——**动它们 git 完全无感**，且正是当前最脏的地方；
2. **再做 P4**（10 个 rename，低风险，立竿见影让根目录回到白名单）；
3. **P2 单独议**：`tools/` 里 5 个 `.exe` 被 git 跟踪（**构建产物不该入库**）⇒ 建议"**先加忽略 + 从索引移除**"，再谈合并目录；
4. **P6 最后做，且先加"分类映射表"**（`docs/INDEX.md` 记旧→新路径），否则历史引用断裂、搜索失效。
