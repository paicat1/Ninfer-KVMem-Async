## 〇、结论

1. **刀6 的错不在"节流"，在"节流可能盖住提问所在的那一拍"。** 打分是 query 条件的，而提问通常在 prompt 尾部；尾部漏拍 ⇒ 针块分数永远反映"问题还没出现时"的相关性 ⇒ 逐出后不再进 kept ⇒ 永不回填。
2. **无损替换不是"调周期"，是"尾部必打 + final 重算 + 补偿腾槽后重搬"。** 主体节流收益保留，尾部代价只有 1–2 次打分。
3. **主战场是池满格（刀6 vs 刀5 = 668.6 s 历史实测差），不是 p2 深超池（节流只值 ~9 s = 13%）。**
4. **所有数值门留白**，等两次复测（退役后冷池 / 池满）回填；否则判据分母是推算值。

## 二、根因：为什么"尾部漏拍"会丢针

### 2.1 机制（待日志轨迹判生死，不写作定案）

```
打分是 query 条件的：chunk N 打分时，用该 chunk 的 query 给所有已有块打分
阶段的压力区 ≈ prompt 尾部（120K 语料下 window_tokens 64,384 起）
PERIOD=8 ⇒ 每 8 个 chunk 打一次
⇒ 最后一个 chunk（提问终点）落在打分拍上的概率 ≈ 1/8
⇒ 针块在多数相位下，分数只反映"问题尚未出现"的相关性
⇒ 得分低 → 被 demote → 不在 kept → restore 不搬 → 答案错
```

### 2.2 行为层证据（已钉）

- `PERIOD=8` 三跑全 K2（丢中段针）；`PERIOD=1` 三跑全对 ⇒ 行为相关成立。
- **但 P2 的 3/3 全丢是同语料同 chunk 划分 = 固定相位的重复，不构成独立采样**；它钉死的是"该相位丢"，不是"任何相位必丢"。

### 2.3 "1,649 之谜"——不是矛盾，是行粒度

```
B 臂压力区 SELECT 表观间距均值 1,649 tok ≈ 4.3 chunk，而 PERIOD=8 应为 8×384 = 3,072
```

**源码（11-14 快照；行号仅在快照内已核，对 11-24 现树有偏移，见 §七）**：

```
kvmem_score.h L522-523  注释自述「短 span 与切段后的长 span 都会出现」
kvmem_score.h L525-529  KEPT 行：无条件 fprintf，打印全部块号
kvmem_score.h L532-546  SELECT 行：无条件 fprintf，无去重守卫
                         （对照 context.cpp L3038-3056 的 restored 行有 last_* 变化检测）
L536-537                格式串含 chunk_abs= / span_mode= / span_local=
```

**⇒ SELECT/KEPT 是 span 级打印，一轮多 span 多行**；若一轮 2 个 span，表观间距 8/2 = 4 chunk = 1,536 tok，与实测 1,649（4.3 chunk）吻合。

**⇒ 结论：PERIOD 的"轮粒度"大概率没坏，坏的是"拿行间距当轮间距读"。** 判定方法（零成本）：`chunk_abs` 去重后算真实轮间距。

**口径更正**：C 表里「B 臂 1,649 与 k6 req#1 1,810 同族」的对照，实为**行间距**对照；两格 span 划分一致时相对结论仍有效，登记表述须改注"行间距（span 级）"。

## 三、已撤回的四项（含两方各自的错）

| 项 | 原说法 | 撤回理由 |
|---|---|---|
| **RECENT=4096 解 K2** | 尾部保护带可救中针 | **对中针无效**：首次 demote 在 window 64,384 ≈ page 1,006，RECENT 4K = 64 页 ⇒ 保护带 = 页 942–1,006；中针 937 在带外（差 1 页）。RECENT 是**位置带**，救尾部新页，不救中部旧针 |
| **RECENT 接线待确认** | 需 grep 现役代码看是否接入 kept | **更强的前提**：选择结构默认即 0（`kvmem_select.h` L61-63 `recent_blocks = 0; // 0 disables it`；L13-16 官方参考实现同为 recent=0）；**且 LUMMY 引的「B2 定案 L2387 → 硬编码 0U」属误引**——构建史 L2387 的 B2 是 `NINFER_KV_WINDOW` 的读码定案，与 sink/recent 无关。**⇒ "sink/recent 是否有 CLI 接线"仍属待钉，但 RECENT 已退出 K2 解法清单，只剩远期防抖价值** |
| **三查③ 用 `recent_blocks=` 判接线** | 恒 0 ⇒ 未接线 | **不成立**：该字段是探针 `scfg` 镜像（L479 明文「只影响这一行日志；本探针不改可见集」） |
| **`skip=` 可判 PERIOD** | skip=1 = 跳过也打印，数分布 | **语义相反**：`skip = n_blocks − kept.size()`（L517），是**选择丢块**度量；`skip=0` 正是刀5 池内恒等形态。数它会得到与 PERIOD 无关的分布 |

另：**「①（候选剪枝）是唯一既快又不丢针的路」不成立**——1b 数学等价、低风险，①只是收益最大。

## 四、刀6′ 设计

### 4.1 三处结构

| 结构 | 内容 |
|---|---|
| **触发范围** | **仅超池/压力区**。池内格保持刀5 现状（无压力零打分）⇒ **冷池 156.7 s 零改动** |
| **尾部必打** | 压力区**最后 1–2 个 prefill chunk** 强制打分（"轮"= prefill chunk，不是 restore 轮——后者 100+ 轮会 +250 s，收益归零） |
| **final 三步** | ① final scoring（压力区路径）→ ② **补偿 demote 腾槽** → ③ restore。缺②会撞 `context.cpp` L1652 `free_runs().empty() → break`（**现役待钉**），门打不开 |

### 4.2 判据（数值门留白）

| # | 判据 | 门槛 |
|---|---|---|
| ① | 三针 **155 / 937 / 1797** 全 PASS（`ZX-7001` + 中段 + 尾段） | 硬门，不过即作废 |
| ② | 针块出现在 **final restored 集合**（不是 kept） | 硬门 |
| ③ | 池满二次 fill | **≤ ___ s**（等复测基线填） |
