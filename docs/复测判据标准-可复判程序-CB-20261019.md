# 复测判据标准：可复判程序（2026-10-19 立，CB）

- 依据：`docs\审核-本批0-8与诊断体系公信力审计-TeleAgent-20261019.md` §六（TELE）——**同一判据源**
- 目的：把"某批 0/N 是测量失败还是承诺失败"从**一次性判决**变为**可重算的程序**，任何复测都能复判

## 一、可复判程序（三步）

```
步骤 1  测 A 是否成立      A = 触发条件（AND：外压 ≥400 MiB 且 自由显存 <400 MB）
                          ⇒ 不成立 ⇒ 本批不在检验域内，既不能证承诺失效也不能证其成立（记为"未验证"）
步骤 2  A 曾成立          历史同配置下 A 成立过吗？（引用原始记录，不采信转述）
                          ⇒ 不成立 ⇒ 承诺本身的检验域需重新声明
步骤 3  B 是否现           B = 被承诺现象（谷：探针口径 decode<60 或 host/round 显著变慢）
                          ⇒ A 成立且 B 未现 ⇒ 才是"承诺面临反例"，需启动复核

判定输出三选一：MEASURE-FAIL（测失败） / PROMISE-CHALLENGED（承诺受挑战） / PROMISE-HELD（承诺成立）
```

## 二、执行门（起跑前必须全绿，缺一即不得开跑）

1. **自由显存直采**：`nvidia-smi --query-gpu=memory.free`（**禁止用"总量 − used"推算**）
2. **口径统一**：承诺用什么口径判，复测就用什么口径测（谷判据主口径 = **探针** `aba_client.py probe`，不是长请求）
3. **决定性指标落盘**：`host/round`（ms）+ `clk` + `pow` + `util` 每轮落盘（不能只 Write-Host）
4. **适用域 5 元组声明**：池 / 口径 / 量化档 / 采样参数 / 样本数 n——**逐项写明，unknown 就写 unknown**
5. **双向闭环**：施加 → 观测 → 释放 → 恢复（30 秒内回基线）

## 三、明令禁止（本批教训固化）

| 禁止项 | 本批实例 |
|--------|---------|
| 混口径比较 | 用长请求引擎口径 50.6–87.3 去比探针判据 decode<60 |
| 推算值代替直采 | free=538 系"总量 16303 − used 15765"推算，非 `memory.free` 直采 |
| 存在性证据写成普遍性承诺 | 3/3（n=3）被表述为"≥400 MiB ⇒ 触发/必中" |
| 未采决定性指标即下结论 | 未采 `host/round` 就断"非谷" ⇒ 应降级为"未检验" |
| 单变量未受控 | PCIe Gen5→Gen4、池 65536 vs 历史档、件/采样变更均未隔离 |

## 四、结论措辞规范

- 证据充分 ⇒ 直接断言（"非谷"）
- 证据不足 ⇒ **必须写"未检验 / 未验证"**，不得写成"已判定"
- 承诺类表述 ⇒ 必须附**适用域 + n + 口径**，否则视为过度断言
