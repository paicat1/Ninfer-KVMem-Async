# 快速上手

三步：**编引擎 → 下模型 → 起服**。引擎自编约 1 小时，本仓暂无预编译 Release；模型直接下载、免加工。

## 1. 编译引擎

前置：Windows · VS2022 BuildTools（C++20/**CMake ≥3.28**——VS 自带 3.26 会拒配 · Ninja）· CUDA 13.x · vcpkg · Git。非 RTX 50 系显卡把 `-DCMAKE_CUDA_ARCHITECTURES=120a` 改成对应值（RTX 40=89、RTX 30=86，`SM120_NATIVE=ON` 一并去掉）。

```bat
git clone https://github.com/paicat1/Ninfer-KVMem-Async.git
cd Ninfer-KVMem-Async
git clone -b engine-main https://github.com/paicat1/Ninfer-KVMem-Async.git engine-src\src-tree\fusion-engine-src
```

编辑 `build\s6_1208a.bat` 头部 4 处路径：`VCPKG_ROOT`、`PATH` 里的 ninja 与 CUDA bin、`SRC`（= 上面 clone 的源码位置）、`BUILD/LOG`。**编译前先在 VS 环境里**（`vcvars64.bat`，不 init 会报 `c1083 cstddef`）。然后：

```bat
build\s6_1208a.bat
```

冷编 60-70 分钟（1042 步）。**产物验收必做**（[配方规范](规范-引擎编译配方-正确姿势与配方级事故-CB-20261020.md) §1 步骤 4）：`cuobjdump --list-elf <exe>` 全 sm_120a、0 sm_86、无 PTX-only——不过门 = 启动假死（CMake 行已内建 `120a`，勿删改）；产物落位 `engine\self-built-20261008\`，记 sha256。

起服报 `0xC0000135` 静默退出 = 缺运行时 DLL：把 `cublas64_13.dll`（CUDA bin）与 `avcodec-62` / `avutil-60` 等 ffmpeg 套件 DLL 拷到 exe 同目录（只补 ffmpeg 新版不够）。

> 引擎源码基底 = 上游 [1314521gjy/ninfer-fusion-kvmem](https://github.com/1314521gjy/ninfer-fusion-kvmem) @ `engine-v0.11.0-kvmem-20261008` + 本仓 20 补丁（I3b 链/异步页流水 ledger 系列/W1-W4）。想从上游源码逐步打补丁而非用 engine-main 分支，命令序列见 [README · 从零复现指南](../README.md#从零复现指南) B 路径。离线备选：`repro/*.bundle` 快照。

## 3. 起服

```bat
ninfer_launcher.py        # GUI，选预设即起服（六开关自动注入）
curl http://127.0.0.1:8094/v1/models   → 返回模型名即活
```

banner `skeleton=80` = KVMem 六开关生效。完整命令行（含全部参数）见 [README](../README.md#快速开始已有引擎与模型时)。

首次起服预期（4070 Ti S 实测参照）：设备档表没有的卡会先做一次校准（~54 s，正常，非卡死）；池起不来按步进往下调（如 65536 差 84 MiB → 57344，即 int8 上限档）；跑通后的参照值——数数字 decode ~140-150 tok/s、召回 4/4 全对、超池 87K 首轮 TTFT ~110 s、续聊 cache 100% / TTFT ~0.6 s（差异大先查六开关与池配置）。

## 必读的坑

- **池 ≥ 预期最大 prompt**（超池有页账风险，中段内容靠检索、口径会变）；
- **单并发**（KVMem 环硬约束，`--max-concurrency >1` 拒启）；
- **别开 `--kv-lease-growth`**（深超池输出被砍）；
- **KV 档**：SWIFT 上用 `rk8v4`；
- **PCIe 建议 Gen4**：Gen5 + 显存争用触发 WHEA 风暴；无符号构建在 Gen5+外压下卡死（带符号件正常）；
- 死亡谷（时段性慢态）已知可控：[FAQ](FAQ-死亡谷-20261016.md)。
