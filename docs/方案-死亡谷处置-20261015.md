## 4. 第 1 步：引擎件

### 4.1 PDL 关闭 = **启动参数，不是代码改动**

```
env  NINFER_PDL_OFF=1        # S7 启动语义；S8 自报核验（DISABLED）
```
- **捕获期生效**（`pdl.cuh` L109 的 `pdl_kill_switch()` 启动时定）⇒ 必须重启起服；
- S10 标志文件只影响**新捕获的形状**，对已捕获图无效（实测 0 次切换行）⇒ **不用它做判决**；
- 回退 = 去 env。

### 4.2 新增打点（唯一需要写代码的部分）

| 打点 | 位置 | 说明 |
|---|---|---|
| **物化段** | `context_kv_materialize` 调用前后（`ops\context_kv_materialize\materialize.cu`，`enter_streaming():411` / `enter():459`） | **TELE P2-①：必须加**——这是自家 §12.2 的 ⭐⭐⭐ 一号等待点；缺它则"自旋在物化链上"时指不到 |
| **forward 内 op 组** | `run_layers(Phase::Verify)` 内（`text.cpp` 族） | 按**实际代码**划分（embed / GDN gating / GDN recurrent / sliding-window attention / MoE-GEMM / lm_head 为预期方向，**以读码结果为准**） |
| **draft 内** | `execution\draft.cpp` / speculative round | **先读实现再定分段数与段名**（不预设） |

**取舍说明（TELE P2-①）**：`candidate_selector`（接受路径）**暂不单独打点**——S9 实测 accept≈0.01 ms，非瓶颈；若槽位允许则廉价附带，不允许则不占槽。

**复用现有机制**：`step_graph_profile.h` 段戳（S6 五槽 / S9 槽 7–8–9），慢轮才打印。

**硬前置（开工第一件事）**：读 `step_graph_profile.h` 确认**槽位预算与打点 API 签名**，读 `run_layers` 与 draft 路径按实际代码列分组。

### 4.3 仪器门（TELE P1-2：打印门与判据的错配，必须显式）

- **打印门（头文件原文）＝总跨度 >100 ms 才打印** ⇒ **30–100 ms 的慢轮不会打印**，"读出 op 组"对它们不可得；
- 因此：**谷的检出不能只靠打点**，必须保留夜班那套多通道判据（探针 decode + `verify` 毫秒 + 行数新鲜度），打点只负责"指名"；
- **健康基线**：健康轮默认不打印 ⇒ 必须做**有界 VERBOSE 采样**并预登记：同形状、同缓存态、固定节奏 N 轮，记录每轮 verify/decode，作为"慢轮 vs 健康"的对照底；
- **Σ 会计规则（TELE 重点审②，预登记）**：**Σ(各 op 组耗时) ≈ verify 总量（±10% 容差）**；若对不上 ⇒ 存在"未归属区"，不得读作"各 op 组均匀"。

### 4.4 观察者效应自检（TELE P1-3：协议量化）

上游实测其探针把入场阶梯 2.424 s → 8.993 s（×3.71）⇒ 打点可能改写被测系统。**预登记协议**：

| 项 | 值 |
|---|---|
| 设计 | **交错 A/B/A/B**（A=无戳件 step11，B=有戳新件），**n ≥ 7 轮/臂** |
| 控制 | 同形状（45KB/200-tok）、**同缓存态**（每轮前先发一次同 prompt 预热）、同起服参数 |
| 主判据 | **`verify` 毫秒（中位数）**；次判据：decode；辅证：输出 sha 逐字一致 |
| 弃用规则 | 主判据两臂差 **>2%** 或 sha 不同 ⇒ **本仪器作废**，退回"只关 PDL"最小方案 |

### 4.5 构建与部署（TELE P1-4：零行为门进链 + 成本重报）

```
build\s6_1208a.bat（--parallel 6） → archive_build.ps1 归档 → engine_ctl start/waitready（§9.1 参数）
```

**成本更正（v2）**：op 组打点大概率要**扩槽**（现 0..9 槽语义已满，头文件在案）⇒ **改头文件 = 全量重编，不是 ~10 min**；按 `--parallel 6` 估 **20–40 min**。成本表见 §7。

**零行为门（S2/S3b 门规，进部署链）**：新件必须先过"**开/关两臂 sha 逐字相同 + decode 零变化**"才算可部署；不过则回退。

## 5. 第 2 步：零负载常开监测

### 5.1 真实成本（口径已更正）

引擎必须起着：**显存 ~15.7–15.8 GiB**（nvidia-smi 现行口径；权重上卡 ~12.3 GiB）+ 空闲 CPU；**零负载**。
（v1 误写的"6.8 GB 显存"实为**引擎进程工作集（宿主内存）**，已撤。）

### 5.2 判据（先验，已按 TELE P1-1/P1-2 修订）

| 观察 | 结论 | 下一步 |
|---|---|---|
| 窗口内出现慢轮（探针 decode<60 或 fresh verify≥30）**且 PDL 已关** | **C1 出局**；同时读打点指名 | 进第 3 步 |
| 慢轮且打点可读，**单一 op 组（含物化段）占比 >60%** 且 Σ 会计规则通过 | 指名归因 | 进第 3 步 |
| 各 op 组均匀（Σ 规则通过） | 自旋不在某个 kernel，在**调度/等待层** ⇒ 查 13 个等待点的等待语义 | 进第 3 步（B 路） |
| **未复现（48 h 无慢轮）** | **只交付"未复现（窗口未证实开启）"**——**不得读作 C1 成立、不得读作已根治** | 交付报告并停 |
| 慢轮出现在 **OFF 期**（若曾开 PDL 对照） | 必须做 **OFF-同一性声明**（TELE P2-②）：其指纹（spin-stamp 段形、target/draft 比、verify 分布）须与 ON 夜病理并列比对，相同才可称"同一病理" | 据此定第 3 步 |

### 5.3 终止条件（写死）

① 抓到 1 个慢轮并读出 op 组 = 成功；② 48 h 无慢轮 = 交付"未复现"并停；**禁止**把监测变成无终止长跑（DECISIONS #34）。
