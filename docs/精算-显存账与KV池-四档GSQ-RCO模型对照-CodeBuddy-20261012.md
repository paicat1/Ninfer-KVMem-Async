## 0. 口径与三个硬锚（一切计算的基石）

**锚 1 · 页账（最精确）**：`1 页 = 64 token`；`rk2v4-e8 下 1 页 ≈ 0.83 MB`
- 构建史四组页数-容量对全部 = 64 tok/页：8,192/128 页、20,480/320 页、32,768/512 页、40,960/640 页、55,296/864 页、65,536/1024 页
- ⇒ **1 GiB ≈ 79,000 token**（rk2v4-e8）；每 token ≈ **13.0 KiB**

**锚 2 · 标定差**：55,296 → 65,536（+10,240 token）恰需 +128 MiB（`--cuda-graph-allowance-mib 128` 补缺起服）
- 10,240 × 13.0 KiB = 130.0 MiB ≈ 128 MiB ✓（±2%）

**锚 3 · 理论构型**：16 全注意力层（64 层 4:1 混合）× 8 KV heads × 128 head_dim
- rk2v4-e8 = K 2bit(256B) + V 4bit(512B) + scales/e8(64B) = 832 B/层 → ×16 = **13.0 KiB/token** ✓
- k8v4 同法 = 1600 B/层 = 25.0 KiB/token —— 与教程"每 token ≈ 25 KiB（k8v4）"逐字吻合 ✓

**锚 4 · 权重实测**：当前上卡权重 = **12.30 GiB**
- README 显存账："权重 12.3 GiB + 高速池/工作区 1.9 GiB + 视觉，free 490 MiB"
- 构建史实测：Q8MTP 版 `loading weights | 12.5 GiB`（10-10 00:32）− iq4_nl 头省 212 MB ≈ 12.29 GiB ✓ 双源吻合

**当前池标定（本库实测）**：40,960 稳定 → **51,200 稳定** → **55,296 贴边**（缺 17-50 MiB 随桌面波动）→ **65,536 实测成功**（需 graph128 + 净桌面 ≤~1.0 GiB）
- 用户"卡在 55K 左右" = 55,296 贴边口径 ✓

## 3. 能力对照（换过去能力怎么变）

**3.1 底座差异（最大变量）**：Swift-1.5 = Qwen3.8-27B 的"推理高效型"微调（UkisAI）——**与你现役 Coder390-EfficientThink 同为公司，但微调方不同**。
- 官方 BF16 基准（ukisai.com）：比 Qwen3.8-27B 少 **58.5%** 思考 token（中位），8 项基准 6 项不降反升：
  - **LiveCodeBench v6 76.76 → 81.71（+4.95）** · **Terminal-Bench 2.1 69.21 → 72.13（+2.92）** ← 编码/agentic 向增强（正是本线用途区）
  - GPQA +0.31 · C-Eval +0.92；略降：ERQA −2.05 · AIME −2.67 · HMMT −2.00 · IFBench −1.46
- 训练路径：RL + 同策略蒸馏，聚焦**长时程 agent 与编码任务**（与 DSH agentic 用途吻合）。
- ⇒ **换底座 ≠ 降级**，是"换任务画像"：编码向大概率持平/更强，纯推理向略弱（参考量级：1-3 分）。

**3.2 量化损失（GSQ-RCO 方法层面）**：
- GSQ（Gumbel-Softmax 学习网格+scale）+ RCO（黎曼约束逐张量比特分配），2026 新方法，卖点 = 同体积优于统一/传统量化。
- ISTA-DASLab 官方数字（经引述）：2.75bpw 档零样本综合均分 **75.70 vs BF16 74.34（+1.36，含噪声）**；与同体积 Unsloth UD-IQ2_S 比：**AIME25 +10.0 / GPQA +8.6 / LCB +4.6**。
- 四档内部质量序（官方 bit budget）：**IQ2_XS < IQ2_S < IQ3_XXS < IQ3_S**（单调）。
- ⚠️ **官方无逐档 KLD**（ModelScope/HF/官网三处均无）——"每档下降几分"没有权威数字，必须本机 A/B。

**3.3 与当前 Q2LynnStyle 的关系**：无同任务对照评测，不做强断言。
- 可见事实：当前容器 13.57 GB ≥ IQ3_S 容器 11.91 GB；标称上 IQ3_S（IQ3 系最高档）≥ Q2Lynn（Q2 系）；GSQ-RCO 分配法晚于 Q2Lynn 配方。
- ⇒ **推断**：IQ3_XXS / IQ3_S 大概率"质量相近或更优"；IQ2_XS / IQ2_S 有质量风险（最小档），以探针 A/B 定案。

## 6. 全矩阵：4 模型 × 5 精度 → 池容量（token，贴边口径）

| 模型 \ KV 精度 | rk2v4-e8 | rk4v4-e8/nvfp4 | k8v4/rk8v4 | int8/fp8 | bf16 |
|---|---:|---:|---:|---:|---:|
| **IQ2_XS**（省 3.96） | **262,144**＊ | **262,144**† | 217,792 | 178,560 | 118,848 |
| **IQ2_S**（省 3.67） | **262,144**＊ | **262,144**‡ | 205,952 | 169,408 | 114,176 |
| **IQ3_XXS**（省 2.36） | 241,728 | 194,592 | 152,192 | 128,704 | 93,184 |
| **IQ3_S**（省 0.80） | 118,464 | 102,592 | 88,128 | 80,192 | 68,096 |

＊ 富余 1.34 GiB；† 富余 0.53 GiB；‡ 富余 0.24 GiB（**过薄，建议不追满，留桌面波动余量**）

**组合推荐**：
- **容量优先**：IQ2_XS @rk2v4-e8 = 全 256K 驻留 + 1.34 GiB 富余 → 富余可试"视觉塔上卡"（口径 1.4 GiB 级，接近持平）或恢复 CUDA graph
- **均衡首选**：IQ3_XXS @rk2v4-e8 = 241,728（几乎全驻留）；或 @k8v4 = 152,192（精度升 1.92× 成本 + 池近 3 倍）
- **质量优先**：IQ3_S @k8v4 = 88,128（精度官档 + 池 1.6 倍）；或 @rk2v4-e8 = 118,464

## 7. 前提、风险与回家验证清单

**硬前提（能不能用）**：
1. 候选为 **`gguf_blocks_v1` 方言**（与 ternary `PQ2_0_G128`/`PTQ1_0_G128` 不通用）——**需确认本线引擎构建支持**；卡片明示"无 layout 的引擎在加载时显式报错拒绝"。
2. MTP 头格式未知（若引擎不吃，用 `scripts/recode_mtp.py` 同法自转 iq4_nl——Coder390 先例 451→239 MB）。
3. 视觉塔继续 `--vision-cpu`（q4/q5_g64 + q8_g32 混合编码，CPU 编码路径沿用）。

**估算风险（±8% 来源）**：Weights 列口径（含/不含视觉塔 ±0.28）、MTP 头重编码 ±0.2、WDDM 桌面波动（±0.1-0.2 GiB，滴流 ~36 MiB/30s）、页对齐取整。

**验证清单（按序）**：
1. 下载 **IQ3_XXS**（均衡档，先证方言可载）→ 起服（先用现定稿参数）→ 看 `loading weights` 行核对预期 ~9.9 GiB
2. 池逐档顶：1024 页（65,536）→ 2048 页+（逐 64 页加）→ 记录拒启阈值；带/不带 graph128 各一次
3. 跑 `scripts/test_ab_arm1.py` 健康探针 + 数数字短测；与现件同 prompt 对比 decode/prefill
4. 能力 A/B：同一条 DSH agentic 任务两件各跑一轮（零截断、思考 token 数、完成质量）
5. 若方位打通 → 补 IQ2_XS（容量极）与 IQ3_S（质量极）实测
