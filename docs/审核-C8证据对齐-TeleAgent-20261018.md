## 一、总体结论

1. **同一现象、同一条支线**：C8"图调度/驱动层"＝ 10-13 设计稿的 **B 候选"提交/驱动侧卡"**（原文："host 阻塞在 `cudaGraphLaunch` 里但 GPU 空转"，设计-挂账46 §14）——经历 **提出（10-13）→ 被排除（10-14）→ 复归（10-15/10-16）→ 钉死（10-17 nsys）** 四段弧。10-17 nsys 是它的第三代证据，也是最硬的一代。
2. **两处否证，均指向历史"排除逻辑"失效**：① 10-14 对 B 的"排除"（依据"util 99.8–100% ⇒ 图在执行"）被 nsys 推翻（谷期内核几乎不跑而 util 仍 100%）；② "饿死并行核 8×"撤回，连带 **C9 的"反证"依据失效**。
3. **关键判据从未干净执行**：C8 判据列"图内 vs eager 对比"唯一一次尝试（E 臂：graph 0）落自愈窗、且池变量混杂 ⇒ **"graph 关是否免谷"至今是开放问题**；而它恰是对着 nsys 靶点（`cudaGraphLaunch`）的**直接干预实验**。
4. **可行化条件已具备**：按需复现（400 MiB ⇒ 100% 命中）使该实验可在**确认的谷态**下干净执行（＝共识排序④"关/缩 graph A-B-A"；前置"查合法性+代价"仍然必要）。

## 四、对齐后的状态修正（建议，供 CB/用户）

### 4.1 C8 候选行建议更正（供 CB 采用，他方件由 CB 自行落笔）

- 原文（构建史 L2679）："**弱未排**：`-Graph` 旋钮二分只说明预算无关，不等于图机制无关 | 图内 vs eager 对比"
- 建议更正为："**提交支已钉死**（10-16 `submit≈wall` → 10-17 nsys：`cudaGraphLaunch` 497 ms 中位/94.5%、内核几乎不跑）；**'为什么卡'未闭合**（三子候选：驱动序列化/校验 · 页表就绪 · 碎片化）；**'图内 vs eager 对比'未做**（E 臂落窗+池混杂）⇒ 关/缩 graph A-B-A 为直接干预实验（前置：合法性+代价）"

### 4.2 C9 状态复核提示

"反证"依据 = "若被抢占，并行微基准不会被饿死 8×（是我方核占着 SM）"（构建史 L2680）——前提"饿死 8×"已于 10-15 撤回 ⇒ **反证链失效**（不等于 C9 成立；仅"反证"标记不再可用）。

### 4.3 顺带闭环一项悬疑

10-15 §25.4"健康态对照待取"——**已由 10-16 数据闭环**：外部 1-thread 核谷态 5.5–6.4 µs / 健康 6.4–14 µs（研判-驱动提交 L50）⇒ 同量级、**该指标无判别力**（与 §25.4 预判一致）。

### 4.4 E 臂历史判定复核（防误读）

"非因果"判定**成立**（唯一成功读数 167.1 落 12:44 自愈窗；与 D 首轮 167.8 同窗；TELE 指令件 L56 佐证）——但**不可读作"graph 关无效"**：该臂 ① 未在确认慢态下执行 ② 池 40960 与 graph 0 双变量混杂 ③ 无复跑/三明治。⇒ 该判定的正确含义 = "证据不足"，**"图关是否免谷"仍为开放问题**。
