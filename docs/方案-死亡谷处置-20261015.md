## 4. 第 1 步：引擎件（补丁级设计）

### 4.1 PDL 关闭 = **启动参数，不是代码改动**

```
env  NINFER_PDL_OFF=1        # S7 启动语义；S8 每窗自报核验（DISABLED）
```
- 语义：**捕获期生效**（`pdl.cuh` 的 `pdl_kill_switch()` 启动时定），故必须重启起服——本就可接受（重启本就重置状态）；
- S10 的标志文件（`NINFER_PDL_FLAG_FILE`）**只影响新捕获的形状**，对已捕获图无效（实测 0 次切换行）⇒ **本方案不用它做判决**；
- 可回退：去掉 env 即回。

### 4.2 新增打点（唯一需要写的代码）

| 打点 | 位置 | 内容 |
|---|---|---|
| **forward 内 op 组** | `run_layers(Phase::Verify)` 内（`text.cpp` 族） | 按 op 组计时：embed / GDN gating / GDN recurrent / sliding-window attention / MoE-GEMM / lm_head |
| **draft 内** | draft 路径（`execution\draft.cpp` / speculative round） | draft 段内再分 2 段（先读实现再定，**不预编清单**） |

**复用现有机制**：`step_graph_profile.h` 的段戳（S6 五槽 / S9 槽 7-8-9），**慢轮才打印**（这是它便宜的原因）。

**开工第一件事（硬前置）**：读 `step_graph_profile.h` 确认**槽位预算与打点 API 签名**，读 `run_layers` **按实际代码列 op 组**——本方案不预设 op 组清单，避免写错。

### 4.3 观察者效应自检（科学对照，先验判据）

上游实测其探针把入场阶梯 2.424 s → 8.993 s（**×3.71**）⇒ 打点本身可能改写被测系统。

- 判据：同形状（45KB/200-tok）× 3 轮，对比**加戳前/后**的 decode 与 verify；**差异 >2% ⇒ 本仪器作废**，回到"只关 PDL"的最小方案；
- 输出稳定性：同形状输出 sha 必须逐字一致（历史已验证）。

### 4.4 构建与部署（既有链，无新工具）

`build\s6_1208a.bat` → `scripts\archive_build.ps1` 归档 → `engine_ctl.ps1 start/waitready`（老档参数见 §9.1）→ 核验 `PDL: programmatic … DISABLED`。

## 5. 第 2 步：零成本常开监测

### 5.1 真实成本（不隐瞒）

引擎必须起着：**约 6.8 GB 显存 + 空闲 CPU**（当前引擎已关，起服即恢复此成本）；**不打负载**（区别于 S12/S13 那类"加压抓谷"）。

### 5.2 判据（先验）

| 观察 | 结论 | 下一步 |
|---|---|---|
| 窗口内出现慢轮（verify ≥30 ms）**且 PDL 已关** | **C1 出局**；读打点指名 op 组 | 进第 3 步（按指名） |
| 窗口内出现慢轮，**单一 op 组占比 >60%** | 指名归因（无论 PL 开关状态） | 进第 3 步 |
| 各 op 组均匀、无单点 | 自旋不在某个 kernel，在**调度/等待层** ⇒ 查 13 个等待点的等待语义 | 进第 3 步（B 路） |
| 窗口内**不再出现慢轮** | **C1 成立且已缓解** | 交付；可选做第 3 步的"保留 PDL 修法" |
| 48 h 无慢轮 | 未复现（或已缓解）⇒ **收工，不续跑** | 交付报告 |

### 5.3 终止条件（写死）

① 抓到 1 个慢轮并读出 op 组 = 成功；② 48 h 无慢轮 = 交付并停；**禁止**把监测变成无终止长跑（DECISIONS #34）。
