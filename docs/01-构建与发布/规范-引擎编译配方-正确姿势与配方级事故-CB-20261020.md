# 引擎编译配方：正确姿势与两次配方级事故（2026-10-20 归档）

- 作者：CB · 日期：2026-10-20 · 用户令：“把正确和原来出问题的编译配方单独写一个文档”
- 定位：本页把散在构建史 §128 / §136 / T#0056 / 决策 #0063 / #0069 里的**配方级**教训固化为单页速查。完整构建细节、机器路径清单、脚本清单一仍以 **`build/README.md`** 与 **`build\s6_1208a.bat`** 为准；本页不复制其全文，只钉"坑在哪、怎么验"。
- 一句话：**① arch 必须显式 `120a` 并以 `cuobjdump` 产物门验收；② 要用于 Gen5 / 外压长跑的构建必须带符号链接（`/Zi` + `LINK=/DEBUG`）。两个条件各欠过一次，就是两次大事故（合计代价：66 分钟冷编报废 + 一个判决实验夜 + 两次错误根因定性）。**

---

## 1. 正确配方（当前唯一定稿）

| 步 | 动作 | 要点 / 出处 |
|---|---|---|
| 1 | `vcvars64.bat` 先 init | 不 init ⇒ MSVC 报 `c1083 cstddef`（环境问题非代码） |
| 2 | 构建（`s6_1208a.bat` 已焊死）：`cmake -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=120a -DNINFER_SM120_NATIVE=ON -DNINFER_BUILD_APPS=ON -DBUILD_TESTING=OFF -DNINFER_BUILD_BENCHMARKS=OFF` | RTX 5080 = sm_120a；**两个 120a 参数缺一不可**；源树读 `engine-src\src-tree\fusion-engine-src` |
| 3 | 产物落位 `engine\self-built-20261008\` | 成品不留构建中间目录（构建目录是中间物，产物是成品） |
| 4 | **产物验收门（不可省）**：`cuobjdump --list-elf <exe>` 核对——384 cubin 全 `sm_120a`、**0 个 sm_86、无 PTX-only**；再看引擎日志 `build` 行；sha256 记 lineage 台账 | 这是两次事故的直接对策；SYNTAX-OK 不算数，**arch 以产物级验收为准** |
| 5 | 若构建件用于 **Gen5 / 外部显存压力**场景：在官方链原样基础上注入符号链接——env `/Zi` + `LINK=/DEBUG`（**offi 配方**，独立构建目录 `build-d1208a`） | §136 判决：无符号构建在该场景卡死不返回，带符号件"谷但完成" |

**linker 注入的机制细节**（§136 实测）：想给 link 加旗标，`CMAKE_EXE_LINKER_FLAGS` 的 env 名**实际是 `LDFLAGS`**（且 CMake cache 会把它固化、后期不可用）⇒ 正确做法是用 MSVC `link.exe` 原生机制 **`LINK` env** 注入（如 `LINK=/DEBUG`）。

## 2. 事故一：缺 arch 参数 ⇒ "启动挂死"（66 分钟冷编报废 + 半天误诊）

- **现象**：sym1/sym2 构建件起服卡死——503 或长时间无输出，预检 11 分钟无进展（同生产件 11 s）。
- **错误根因（当时）**：曾归因为 `/DEBUG` 注入 graph capture 死循环（§127 后被推翻）。
- **真实根因**：`build_sym.ps1` 未传 `-DCMAKE_CUDA_ARCHITECTURES=120a` ⇒ CMakeLists 默认值静默落到 **sm_86** ⇒ 本机 RTX 5080（sm_120a）无法直载 sm_86 SASS ⇒ 回落 **PTX JIT 长征**（357 kernel，50 min 未完），表象与挂死无异。(T#0056 / §128 / #0063)
- **修法**：`build_sym.ps1` 补齐 `-DCMAKE_CUDA_ARCHITECTURES=120a -DNINFER_SM120_NATIVE=ON`（对齐 `s6_1208a.bat` 配方）⇒ sym3 冷编 66 分钟 ⇒ `cuobjdump` 验收 384 cubin 全 sm_120a、0 sm_86、总量与 S13 一致，冒烟通过。
- **教训（已机器化）**：任何 CUDA 构建命令必须显式传 arch；产物验收必须过 cuobjdump 门；**"起服卡死"先查 arch，再谈玄学**。

## 3. 事故二：无符号构建 ⇒ Gen5+外压"卡死不返回"（一个判决实验夜的代价）

- **现象**：S13 生产件（官方链 14.44、无符号）在 Gen5 + 外部显存压力 ≥400 MiB + 池贴边条件下 **decode 掉 0、5/5 探针 30 s 超时取消、请求永不返回**；同条件下 sym3 / offi（带符号构建）= 41 / 44.5 tok/s 深谷但 **6/6 全部完成**。
- **判决方法**（三件矩阵，单变量=符号链接）：S13（14.44 无符号）vs sym3（14.43 +/Zi+/DEBUG）vs offi（14.44 +/Zi+/DEBUG，官方链原样+符号注入）。工具链版本 14.43/14.44 双版本均"谷但完成" ⇒ 版本排除；offi 无 host 开关也走得完 ⇒ host 排除 ⇒ **唯一剩下变量 = 符号链接三开关**。
- **根因定性**：卡死元凶 = **符号链接缺失**。`/DEBUG` 改变链接产物布局本身——不是"符号让我们看见卡死"，是"加符号这个动作治了卡死"。(§136 / #0069)
- **与谷的关系**：谷（慢但走得完）与符号/工具链无关（三件全入谷）；卡死是构建问题（已定位、可制造可回避），谷是负载×环境现象（未闭合）。
- **处置**：日常 Gen4 生产不受影响；**Gen5 / 外压场景换用带符号件（offi / sym3）**，或按本文 §1 步骤 5 重新构建。已写入 README"当前定稿"的选件指引。
- **教训**：构建件的"符号/调试开关"不是纯观测选项，它改变产物布局、可改变运行期形态；对压测/边缘场景构建，符号链接是**配方的一部分**，不是可选项。

## 4. 其他配方纪律（速查）

| 纪律 | 内容 |
|---|---|
| CMake 默认值不可信 | `CMakeLists.txt` 默认 arch 会静默落 86（事故一）；关键参数一律显式传 |
| .bat 注释 ASCII-only | cmd 按 OEM/ANSI 码页解析，中文注释乱码炸构建（本项目踩过） |
| 机器绝对路径 | 8 个复现必需文件写死 `J:\` 路径，清单按行号列于 `build/README.md` §四——改脚本必须同步那张表 |
| 干编译目录 | 独立实验构建用独立目录（如 `build-d1208a`），勿污染正式 cache |
| 产物身份 | 每件 sha256 记 lineage 台账；`engine/lineage/` 一版一件永不覆盖 |
| 交叉印证 | 源码树的 `docs/maintainer/quality-trade-experiments.md` 记录质量-资源旗标的判决数据；构建配方变更后其结论需重新标注适用 build |
