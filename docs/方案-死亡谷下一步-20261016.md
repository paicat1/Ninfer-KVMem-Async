- 日期：2026-10-16 00:4x · 作者：CodeBuddy（家里线）· 用户令：**重新写下一步方案；禁止望天收；禁止挂机假装干活**
- 前置事实（全部已实测）：谷＝慢但走（decode 28 / forward 208 ms / util 98–100% / 功耗 93 W / 外部小核 6–8 µs 不被饿死）· C1（PDL）**出局** · C5/C7 已否 · 首层 op 不动、后层 mixer 膨胀 · 另有 C12（空闲后首请求**永久挂死**、GPU 2%）

## 1. 核心假设（可操纵变量候选表，按先验排序）

谷的指纹是"**核在跑但每个都在等**"（GPU util 高、功耗低、外部小核不受影响）⇒ 候选"在等什么"里，**宿主页路径**先验最高（主机近满 ⇒ 页面回收/换入 ⇒ 每次读宿主页都要等 PCIe/缺页）：

| # | 可操纵变量 | 先验 | 怎么施加 | 怎么解除 | 判据（复现/排除） |
|---|---|---|---|---|---|
| **V1** | **主机空闲内存/页文件压力** | **最高**——谷指纹＝"每个核都在等"；引擎跑在 `HOST_PAGEABLE=1`+`REUSE_HOSTBACKED=1`（宿主页可回收复用）；Watch 实测**空闲内存仅 98 MiB**；C12（空闲后首请求挂死）也属同族 | 用 python 吃满主机可用内存（如 8–16 GB，可控、秒级释放），使页文件活动起来 | 释放那笔内存 | ① 微基准 host 页读延迟显著上升 ② 引擎起服后**立刻入谷**（不必等窗口）③ 释放后谷消失 |
| **V2** | 宿主页**冷热**（回收后再触） | 高——C12 已证"空闲 27 分钟后首请求挂死" | 起引擎 → 空闲 N 分钟（N=2/5/10，实测阈值）→ 探针 | 探针前先"预热"（小请求触发换入） | 阈值可复现 ⇒ 与 V1 同族；预热能避免 ⇒ 缓解手段现成 |
| **V3** | 显存压力/碎片 | 中——谷期显存 15.7 GiB（额定 16.3） | 起服时把池/图额调大压满；或并行占显存 | 降额重启 | 显存贴边时必出谷 ⇒ 变量成立 |
| **V4** | 提交/驱动侧（WDDM 队列） | 中——"核在跑但在等"也可解释为提交被节流 | 并行跑多个大显存/大 PCIe 负载（另一进程做 D2H/H2D 吞吐） | 停掉并行负载 | 并行 PCIe 吞吐上升时谷出现 |
| **V5** | SM 侧共存（外部核） | 低——已实测外部小核 6–8 µs 不被影响 | — | — | 已近似排除 |

**注意**：V1/V2 共享同一部件（宿主页），**若成立则两条病理（谷 + C12）并案**；V3/V4 是独立支路。

## 2. 三步（每步都有终止条件；总预算 ≤ 3 小时）

### 第 1 步：翻旧账找变量（离线，10 分钟，**先做**）

- 把**已有台账**里"谷 vs 健康"的主机态对照出来：空闲内存 / 页文件 / commit / 磁盘 IO / 引擎 WS / GPU 显存；
- 数据源：`.temp\gpu_samples.csv`（23:40 谷期，GPU 侧）· `logs\evidence_*`（谷/健康引擎日志）· 更早的主机检查记录（日报告）；
- **终止条件**：若对照显示某个主机变量与谷**同变**⇒ 提为该步的**首选施加对象**；若**无任何主机变量与谷相关**⇒ V1/V2 降权，**直接跳第 3 步**（改攻 V3/V4）。

### 第 2 步：主动复现（30–60 分钟，**本方案主体**）

**2a 微基准层（5 分钟）**：`tools\concur_bench.exe` 现在同时测 ①外部小核 ②**host 页读**。
- 基线（已可测）：记 host 页读均值；
- 施加 V1（吃内存）后再测：**若 host 页读延迟显著上升 ⇒ 机制确认在宿主页路径**；
- 终止条件：host 页读均值上升 ≥5× ⇒ 命中；否则 ⇒ V1 在该层级被否，转 V3/V4。

**2b 引擎层（15–30 分钟）**：在 V1 施加状态下**起引擎 + 探针 7 次**。
- **判据（按需复现成功）**：`target ≥ 100 ms` 或 `decode < 60` 在**起服后 3 分钟内**出现 ⇒ **不再需要窗口**，随时可复现；
- 若出现 ⇒ 记全证（四层 op 组 + draft 内部 + 微基准三项）；
- 终止条件：7 探针全健康 ⇒ V1 未复现；换 V3（池贴边）或 V4（并行 PCIe 负载）各重试一轮；**两轮都不复现 ⇒ 该支路结案**。

**2c 反证（10 分钟）**：若 2b 复现成功，**立刻解除 V1**（释放内存）并在**同一引擎**上再探 7 次。
- 判据：谷**当场消失** ⇒ 因果成立（这是"施加/解除"双向证据，比窗口对照强）；
- 若解除后仍谷 ⇒ 复现与 V1 无关（可能是"起服即谷"的机器态），记录并降级为"相关性"。

### 第 3 步：若第 2 步全支路失败（≤ 1 小时，**也必须给出结论而非等待**）

按 V3（显存贴边）→ V4（并行 PCIe/提交负载）各做一次"施加/解除"；**全部失败则明确交付**：
- **结论**：谷不由"可施加变量"触发（在本次尝试的变量集内）；其触发条件**指向我们尚未测的第三个维度**（候选：GPU 时钟/温度历史、驱动版本状态、固件/驱动内部状态）；
- **下一步**（也非等待）：① 用 `--host-state-slots`/`HOST_PAGEABLE` 等**档位二分**（关掉宿主页档位后重复第 2 步，看谷是否还能被 V1 复现）② 换引擎件对照（`step11` vs `step12b`，判"我们的补丁链是否相关"）③ 派工上游（把"每核都在等 + 外部核不受影响"的交由上游判断）。
