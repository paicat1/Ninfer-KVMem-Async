## 2. 研判

### 2.1 "多因素"不是猜测——它已是攻关的书面状态

- **状态依赖（最硬）**：同一引擎、同一深负载，窗口内 85 分钟出 5 次谷、窗口外 8.5 小时零谷（证据 #1/#2）——"谷"不是"给定输入⇒必出"的确定性现象，而是"输入 × 机器状态"的乘积；
- **触发路径多态**：外部显存（已定标）、宿主内存（n=1、复现失败）、重复施加+重启叠加（深读数 2.5–3.0s 远深于单次 650ms，候选）、自然自发（候选反例均有活动混杂，未证）；
- **施加≠必出**：61% 施加箱无谷（剂量阈值之外仍有隐藏变量）。

### 2.2 触发侧为何难（难点已聚焦，但成本真实）

1. **窗口成因未知**：时段 / 主机长 uptime / 外部环境均未排除（处置方案 §8）；
2. **事件稀疏 + 观测成本高**：窗口期才有现象；观测要占机器+电+用户授权；
3. **自诱导混淆与观测互斥**：自然谷观测须"禁工具"，而实验动作（构建/重启/施加）本身是污染源——审计（证据 #6）已把这条摆上台面；
4. **基建性坑**：遥测盲区（60 次打印上限）、盲窗管理（11:32–12:37 停摆先例）、仪器陈旧值语义——均在修复/已有纪律，但都消耗时间。

### 2.3 病理侧反而在收敛

- **签名统一**：各次谷均为"util 99.8–100% + SM 满频 + 功耗仅 63–98W"——"在等待，不在工作"的自旋签名，多处观测一致 ⇒ 暗示**存在共同末路**；
- **候选短清单、可判**：PDL（第一嫌疑）+ GDN（备选），处置方案判据为分支决策树（证据 #10），不是"押宝单点"；
- **确定性实验台**：按需触发 10/10 复现（证据 #3）——不受"窗口稀疏"限制的受控实验能力，是当前最强的研究工具。

### 2.4 核心悬疑：三族同源性未证（本报告主张的重点）

当前并存**三个现象族**，彼此"同源与否"没有证据：

| 族 | 形态 | 状态 |
|---|---|---|
| 按需谷 | 外部显存压力触发、恰好 1 探、深度 8–9 | 已定标、可复现 |
| 窗口谷 | 分钟级、verify 200–220ms | 窗口成因未知 |
| 深谷 | verify 1.5–2.5s | 与按需差 100×，未证同源 |

CB 在夜研-2 §6 已自认"未证同一控制量"（证据 #5）。**这个鉴定是"单点 vs 多问题"的分水岭**：

- 若三族同源 ⇒ 按需实验台的结论可外推到全部子现象，修法一刀到底；
- 若不同源 ⇒ 确认"多机制"，则按族配修法、逐族封闭（GDN/PDL/驱动层/槽位各有现成候选）。

在此之前，任何"已找到根因"或"已排除某路径"的表述都应保持口径纪律（现有的"未证/候选/未复现"分层表述是正确的）。

## 3. 建议清单

### 建议 1（主）｜同源性鉴定升格为显式判据

- **动作**：为三族建"签名比对表"，定义统一签名域（建议五项）：
  a) **spin-stamp 段形**（target/draft/total 比例——已有历史样本：ON 夜 `target=227.7 draft=56.2`、深谷 `target=1307.1 draft=485.5`）；
  b) **verify 分层分布**（轻 30–100 / 谷 100–226 / 深 226–500 / 极深 ≥500 四档计数）；
  c) **host 提交占比**（submit≈wall 口径是否同构，夜研-2 新仪器）；
  d) **GPU 指纹**（util / 频率 / 功耗三重）；
  e) **输出同一性**（sha / 逐字）。
- **判据（先验，由执跑方预登记写死）**：任两族在 a–d 上同构且 e 成立 ⇒ 判同源；有实质差异 ⇒ 判不同源（多机制确认）。
- **落点**：①下次窗口谷/深谷捕获时逐项比对（可并入猎人 v2 快照字段）；②按需族作为**机理研究主战场**做深（唯一确定性实验台）；窗口族用猎人抓样本做同源鉴定——两条腿分工。
- **成本**：离线为主 + 少量台账字段；不新增实验负载。

### 建议 2｜坚持"先解决再解释"，但必须与窗口对齐

- **PDL off 长窗验证**：`NINFER_PDL_OFF=1` 起服（捕获期生效、一次重启、代价 ≤1.2%、输出逐字同）——关掉后跑授权长窗，看谷事件是否减少；**无论解释是否写完，先拿证据**；
- **GDN 补丁构建**：已证性能缺陷（少 1/3 并行度），本来就该修；排窗间隙构建、同窗验收；
- **对齐纪律**：窗口不开的零谷不可作功（S12 教训）；两条验证都必须配 VERBOSE + 判据双源 + 到点即收。

### 建议 3｜观测期工具纪律（自诱导教训资产化）

- 任何"自然谷观测期"内：**工具活动全部落台账并标记**（沿用自诱导审计的"施加类/探针类/其它"分类口径），显式区分「禁工具期 / 活动期」；
- **无流量时段与无谷分开记账**（处置方案 §5.2 已有条款，重申执行）；
- **盲窗必记**：监控停摆时段的"无谷"不得计入发生率统计（11:32–12:37 先例的正确处置，已形成惯例，保持）。

### 建议 4｜猎人 v2 追加强化两项

TELE 已首审（有条件通过 + 8 条意见，见 `docs\04-审核与复核\审核-猎人v2草案-TeleAgent-20261016.md`）。追加两点：

1. **两级快照必须带"同源签名域五项"**（承建议 1——活谷目击的价值一半在当下冻结，一半在能与按需族比对）；
2. **VERBOSE 长开 + 轮转保护**（60 次打印上限的遥测盲区条款已有，执行时配日志轮转防膨胀）。

### 建议 5｜预期管理：按"复数根因"编预期与预算

- 最终交付形态建议预设为三件套：**①若干已封闭的触发路径 + ②一个（或几个）已封闭的共同通路 + ③残留风险清单**（含"窗口"本身的未解说明）——而非"单一根因、一击全消"；
- 预算（机器时间/窗口时间/授权时长）按"复数根因"口径编；
- 对外表述口径：在鉴定完成前，沿用"未证 / 候选 / 未复现"分层语言，不用"找到根因 / 已排除"的完成态语言（现有文档已基本合规，保持即可）。
