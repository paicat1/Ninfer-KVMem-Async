## 二、三条结论（含一条**首次限定**）

1. **深上下文内容完全可复现**：同配置两次起服（d_rk65 / d_rk65b）两轮输出**逐字相同** ⇒ 60K 下引擎仍确定、无状态噪声。
2. **【首次限定·A2 门适用域】超池会改变内容**：同格式（rk2v4）、只差池大小 —— `40,960（超池 19K，demote 88 页）` 输出 `78bcb798` ≠ `65,536（装得下，~0 页）` 输出 `8b3a141f`。
   - **机制解释（非损坏）**：超池 ⇒ **KVMem 检索/选页介入** ⇒ 模型看到的是"被选出的上下文子集"，输出自然不同（这是 KVMem 的设计行为）。
   - ⇒ **A2 lossless gate 的正确适用域 = 工作集 ≤ 池**；此前"谷=时间现象、内容不变"的结论在该域内成立（浅上下文 + 活体谷窗实测均通过）。
3. **"池 ≥ 工作集"获得第二条理由（比速度更硬）**：不只是少搬运，而是**数值透明性/可比性** —— 任何 `上下文 > 池` 的运行**不与** `上下文 ≤ 池` 的运行可比；**黄金 SHA 门禁、逐字门必须在"池 ≥ 上下文"条件下跑**，否则测的是检索子集的影响。
4. **附**：nvfp4 的 prefill 明显更慢（998 / 624 tok/s vs rk2v4 的 1,570–1,659 / 845–953）⇒ 每 token 字节 +1.42× 在**写路径**上也可见（此前只看到 decode 持平）。
5. **81,920 不要用于运营**：同配置 19:13 能起、19:32 **差 3.4 MB 拒启**（`requires 2,018,246,912 > available 2,014,855,168`）⇒ 贴边档；生产取 **65,536**（本批 free 489.6 MiB，稳）。

## 三、对既有文档的修订项

- KV A/B 结论不变（浅上下文批次在池 ≥ 上下文条件下完成，逐字门有效）；深上下文批次**不参与**跨档内容对比（各臂超池量不同）。
