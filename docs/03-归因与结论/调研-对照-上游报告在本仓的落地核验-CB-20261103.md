## 二 报告未覆盖、本轮核出来的三条

### 2.1 `--adaptive-mtp` 是我们现成但从未测过的实验点

- 实现完整度**高于 Strata**：Strata 是 4 桶先验（`kPriorQ = {0.75,0.88,0.93,0.96}`，按 match `<6/<12/<24/≥24`），我们是**逐请求 3..15 宽度**、按"drafts 实际存活到第几"选宽（`mtp_adaptive.h:3`）。
- 状态：**launcher 默认 `adaptivemtp=off`**（`ninfer_launcher.py:540` "定稿 k3 固定不变；opt-in 开启"）。
- ⇒ 报告把"已有功能"当成"要借外部实现"，与我们自己 10-31 已接入的事实冲突。**不需要写代码，只需要开一次实测。**

### 2.2 KV_PREFETCH 的可借性被高估：我们已经是逐层事件流水

关键代码链：

```cpp
// prefill.cpp:1130-1131  （patches 版同款）
// The first pass after a Host restore waits for each layer's copies (hybrid spec §6.5).
schedule_state.layer_ready = hybrid_take_restore_layers(sequence.lane);

// execution/text.cpp:1223-1224
if (layer < layer_ready_.size()) {
    CUDA_CHECK(cudaStreamWaitEvent(ctx_.stream, layer_ready_[layer], 0));
}
```

⇒ 结构 = "拷贝在独立流上逐层推进并记事件；计算流在第 i 层前只等第 i 层"。
**这不是"一层等全部"，也不是"全部等完再算"**，而是逐层重叠。

因此报告 §2.15 的 "939 ms / 1,553 ms serial KV-stage wait 移出关键路径" **不能直接套用**：我们的同类等待已经被事件化。真实剩余收益取决于 **每层 restore 拷贝时间 vs 该层 prefill 计算时间** —— 只有拷贝更慢时才暴露。

**判定：此项从"✅ 可借"降级为"⚠ 需实测确认剩余暴露"，且不应作为 prefill 优化的第一优先。**

### 2.3 DFlash2 的引擎侧证据（补强报告 §12.3）

报告列的是 `dflash.cpp / draft.cpp / q8_dflash2_*.cu` 等静态文件。
本轮在**预填执行路径**里找到运行时接线：

```cpp
// prefill.cpp:1104-1121  PrefillContext 构造里直接带 dflash
dflash ? &*dflash : nullptr,
// prefill.cpp:1175-1179
if (is_masked_draft_backend(speculative_backend)) {

```

⇒ **不只是"有代码"，是"预填主循环已经在调它"**。DFlash2 的障碍确实只剩容器（模型件里没有 `dflash2/` 组件）。
