## 1. kvmem/kvmem 上游四 PR（2026-10-18~19，WANG Leye + melis2023）

**融合架构复核（与我们的差异，结论不变）**：上游 = 引擎外公共存储层 + 每后端版本化补丁（llama.cpp 与 ninfer 双后端并列）；我们 = 引擎内深改（页流水进 program/storage）。他们是多引擎"存储平台"，我们是单引擎"性能路径"——正交。

### PR #152：DFlash2 16 GB 启动配方 + 256K 对照记录

- 配方：256K 上下文、**B36K/R10K**、FP16 GDN、**五个 DFlash2 草稿**、无 n-gram、**64 MiB graph allowance**；Windows 快捷方式 + launcher 依赖进 worker/console 包；
- 对照记录：五草稿 Task 1 跟进 + 33 请求 Task 2 两轮（对照 RC3 基线），含原始计时/用量/来源/配置差异/"capped-code 输出不完整"的如实记录；
- **对我们的意义**：①同为 16 GB 卡做 256K + 多草稿投机，**他们的 graph allowance 是 64 MiB（我们 128 MiB）**——图预算对池空间的挤压是同一个零和问题，可对照调参；②五草稿 vs 我们 MTP K=4——**投机路线对照组**（他们 DFlash2 侧重草稿数，我们侧重 MTP 链 + ngram 混合）；③"capped-code 输出不完整"的问题我们 DSH 侧也见过（maxTokens 封顶类），口径可对照。

### PR #151：checkpoint 会话恢复的完整 KV 还原（fix/llama）

- 内容：恢复保留会话前**先还原冷态 KV 尾部**；MTP 块仅从**完整打包 K/V 备份**还原并复验恢复视图；**取消后保留可复用前缀**；恢复失败 → **回退全量 prefill**；
- 验证：RTX 5060 Ti 全量 27B 模型，136 请求 + 12 取消 × 4 配置全过；三个 MTP 回滚用例保留 2333 缓存 token 且输出一致；Missing-V 故障注入拒绝复用并冷预填恢复；
- **对我们的意义**：与我们页账的"publish 前不可丢弃 / 取消可回滚"**同域但层级不同**——他们是**会话级快照恢复**（跨重启/会话切换），我们是**页级实时换页**。两个可抄的设计：①"恢复失败 → 回退全量 prefill"的显式降级路径（宁可重算不可错）；②"MTP 块只从完整打包备份还原"（草稿状态与主 KV 同等对待，不拼凑）。我们的取消检查点（挂账 42 施工①）可对照其边界清单做一轮交叉评审。

### PR #153：后端原生遥测对齐 + 投机诊断（MTP canary）

- 对齐两后端的原生统计、暴露投机诊断计数、速度报告消费真实 MTP 输出与轮数；
- **对我们的意义**：我们的 a2gate / 接受率遥测可与其字段定义对齐（接受率/轮数的统计口径统一后，三方数据可直接互比）。

## 2. ActKV 论文（arXiv 2609.31395）——评估：不进主线，两点可无损吸收

**先澄清**：该论文（WANG Zihan 等，cs.OS，2609-09-25 提交）**不是 KVMem/NINFER 的融合论文**——摘要与 kvmem 仓均无涉；是独立的第三方 KV 压缩工作。

**技术内容**：以"KV 条目对**动作生成**的贡献度"为压缩准则，面向 Agent 的"观察-推理-行动"循环：①动作导向淘汰（保留对未来动作关键的条目）②置信度驱动的自适应预算分配 ③页感知压缩原语 + 定制内核。成绩：25.98% KV 内存保留 98.53% 平均准确率，token 吞吐 3.97×。

**有损定性**：淘汰 = 丢内容——**有损压缩**（1.47% 平均准确率损失）。

**与我们的关系**：

| 维度 | ActKV | 我们 |
|---|---|---|
| 解法 | 丢内容 | 移内容（KVMem 召回 + 页流水） |
| 正确性 | 有损（平均 98.53%） | 无损（A2 门逐字相同） |
| 承诺对象 | 平均质量 | 每一个 token（Agent 工具调用错一个 token = 行动失败） |

⇒ **正面冲突：淘汰路线与 A2 无损门不兼容，不进主线**（上游 kvmem 同样选择了无损的虚拟化召回路线——两条无损线在此一致）。

**可无损吸收的两点**：
1. **"动作贡献度"打分信号 → 召回排序**：我们的 restore 召回打分目前基于相关性（mean-K/GQA max）；"对动作生成的贡献度"是更贴近 Agent 场景的信号——同一信号可无损地用于**召回优先级排序**（不丢页，只决定先召回谁的）——直接增强三道过滤器的第三道，并与"误搬率观测"待办合流；
2. **置信度驱动的自适应预算** → 池水位自适应档：我们池旋钮目前静态配置；可借鉴"按模型置信度动态调预算"做水位自适应（仍无损，只是预算更聪明）。

## 3. zxz 线质量栈三开关（引擎原生 env，零成本提速候选——待确认）

zxz README（v140 认证档）冻结的质量栈中，两个开关是**引擎原生环境变量**（NINFER_ 前缀）：

| 开关 | 默认 | 作用 | 质量代价（其实测） |
|---|---|---|---|
| `NINFER_TERNARY_S8=1` | 开 | int8 激活档（T≥33 长预填） | ΔPPL +0.0027（门限 +0.05）；**250K 长上下文答案逐字节一致**；250K 预填 −6.9% |
| `NINFER_STATE_RECURRENT_FP8=1` | 开 | GDN 循环状态镜像 e4m3 | ΔPPL +0.0028；**每路省 35.5 MiB**（并发上限 42→60） |
| `NINFER_STATE_RECURRENT_FP16` | 关（被 FP8 取代） | — | ΔPPL +0.000554 |

**关键问题**：我们的引擎（`paicat1/Bonsai-27B-NInfer` engine-main，与 zxz 同基线 f90e30c1 时代）**是否存在这两个开关**——存在则为零成本提速候选（一句话 env）；不存在则是 zxz 72 文件补丁的新增，吸收需评估补丁面。
⚠️ 外推规则（沿用 10-15 笔记 §2）：其全部质量数字基于 **Ternary-Bonsai-2-27B（~1.72 bit/权重）**——与我方 IQ3_S（3.62 bpw）模型前提不同，**采纳前须在我方 IQ3_S 上过 A2 逐字门与 PPL 门重标**。
