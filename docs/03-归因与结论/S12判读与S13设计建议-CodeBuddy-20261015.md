## 4. S13 设计【v2 · 复现优先版】

**核心原则改写：先复现，后对照——复现优先于对照。**

### 4.1 五要素对齐表（复现组配置）

| 要素 | 对齐对象 | 具体 |
|---|---|---|
| ① 平台 | **老平台**（阳性各例全部是老平台） | Q2LYNN + rk2v4-e8 + 池 65,536 + graph64 + overlay |
| ② 仪器件 | 与夜班同款（**明确 step9 或 step10 一个**，勿混） | S12 用了 step10 + MAT_DEBUG=1——本身即变量 |
| ③ uptime | 长跑制 | 单臂 ≥3h，组内不重启（PDL 属性捕获期烘焙——组内恰不需要切换） |
| ④ 负载 | 夜班矩阵 | 四形状轮换（空转×2 / 深 60K 单发 / 多轮增长跨池 / 超池长解码），每 9 循环轮换 |
| ⑤ 机器态 | **窗口期** | 不可人工制造时刻——**抓到即用**（见 4.2） |

### 4.2 守望升级："抓到即复现"（v2 核心新增）

守望者一旦捕获谷指纹（decode<60 + verify≥30 + 段戳），**自动切进"复现模式"**：

1. 保持长跑（不重启、不切档）；
2. 采样率提高（探针加密 + 段戳窗口盯紧）；
3. 自动开四形状轮换；
4. 冻结旁路（档位 / KV 精度 / 池 / 底座——一律不碰）；
5. 现场收证（段戳 / commit 相 / turn closure 缓存状态 / loadSlow）。

**趁窗口还开着**——窗口时长本轮 ≈14h，错过要等下次"变脏"。

### 4.3 对照（仅当复现成功后）

- 阳性出现后**现场**收"谷的形态与链定位"（运行期 PDL 切不了——现场拿不到 PDL 因果）；
- PDL 因果判决 → 下一窗用 `NINFER_PDL_OFF=1` 起服的 OFF 件做**跨会话对照**（长跑 3-4h）；
- 若两组全 0 ⇒ 窗口外——**等窗口，不做无窗对照**。
