## 4. 疑点候选（只列候选，不下结论）

- C1 `host_kv_arena.cpp:62-65` 的 `dtype_size(plane.dtype)` 对 U8 计划面恒为 1 字节；E8 key 的「64 字节/行」完全由 `head_extent=64` 表达。若某处 geometry 把 E8 key 的 `head_extent` 写成 256（未按 /4 收窄），host 负载会放大 4 倍 → 拷贝宽度与 device pitch 不一致。
- C2 `paged_kv_cache.cpp:765-776`：PageMajor 分支按整页一次 2D 拷贝，非 PageMajor 分支按 `head` 逐次拷贝；E8 的 scale 平面若 `head_extent=1`，两种分支走法不同，任一分支的 `head_payload_bytes` 与 device 侧 `nb[2]/nb[3]` 计算口径若不同即会漏拷或多拷。
- C3 `context.cpp:1636-1673` 的 restore 是「提交 copy → 本步末尾一次 synchronize」；`kv_store.h:1789-1797` 的 `publish_device_replica` 与 `tables_->publish` 都在同一 stream 上排在 copy 之后。**同 stream 有序成立**，跨 stream 无证据。
- C4 E8 decode 是「load 期展开」（`d256_profile.h:70-73`）；若展开读的 scale 与 code 分属不同 plane，而两者在 host 往返中分开拷贝，拷贝完成时点差异是否可能被 attention 观察到——未取证。
- C5 `context.cpp:1638-1641` 明写「partial restore is semantically safe by design — pages that never made it back stay hidden from the mask（silently unreadable）」。若 E8 场景 restore 静默失败，表现为「上下文变少」而非报错，与实测「len 5795 vs 8261、acceptance 72.3% vs 91.3%」同向，但**因果未证**。
