## 0. 核心思路（一句话）

**双智能体异步协作 = "落件信箱 + 心跳 + 握手回执 + 待办队列" 四件套**；双方不靠"对话记忆"存活，靠**磁盘上可回执的状态件**驱动，谁都不依赖"对方上一轮说了什么"——而是**每一轮都读"当前待办 + 当前状态"**。

- **唤醒触发**（自动判据）：
  - **新提交出现** → 我读新台账，进入审核；
  - **台账停长** → 我诊断进程（engine/脚本是否掉线）；
  - **引擎/进程消失** → 落"进程掉线"件提醒用户（我不擅自拉起，机器归用户）。
- **值守不是"无限轮询空转"**（用户禁止挂机）；是**事件驱动 + 有界巡检**。

## 3. 互相激发（防止"各自埋头、互不知情"）

**激发 = 一方落件后，明确"要对方做什么"，且给可验证的目标。**

激发件必含（**TELE→CB** 模板，我每份指令件都带）：
1. **背景**：当前状态一句话 + [EVIDENCE]；
2. **要求**：你要做什么（一条）；
3. **目标/验收**：完成的标准（可测，不空喊）；
4. **截止/节奏**：多久内、什么节奏；
5. **回执要求**：做完怎么回（落哪份件）。

**CB→TELE** 激发同理（落状态件 + 报告，我审）。

---

## 4. 唤醒（把"死等"变成"有信号"）

- **主唤醒**：**git 提交 = 心跳**。CB 每轮必 push；我每轮轮询 git，有新提交即"被唤醒"去读。
- **副唤醒**：`docs\` 出现**新致件**（TELE→CB 或 CB→TELE），文件名带日期，轮询时按**最新件**优先处理。
- **避免"一轮完毕不知对方要求"的关键**：
  - **每件末尾带"下一步要我做什么"**（哪怕一句话"等你审/等我跑"）；
  - **每轮读件先看"待办队列"**（见 §5），不看记忆；
  - **回执**：收到件 → 对方回"已读/已办/阻塞原因"，形成闭环。

---

## 5. 待办队列（不依赖对话记忆的核心）

落**常驻状态件**：`docs\协作状态-当前待办与交接.md`（双方只写、不删他人行）：
```
## 当前主任务（谁负责 · 状态）
## 待办队列（按优先级，每项：谁 / 要求 / 验收 / 截止）
## 握手记录（最近一轮：CB→TELE 回执 / TELE→CB 指令）
## 分歧挂账（未决，等用户）
```
- **每轮开工前先读它**，才知道"该做什么、谁等谁、有哪些没回执"。这是"不丢要求"的物理锚点。
