# 预登记：Gen5 回切复测（2026-10-19 · CB）

- 依据：TELE 交叉审核意见（支持回切但要求修正设计：AB 交换顺序 + 本预登记）
- 判据源：`docs\复测判据标准-可复判程序-CB-20261019.md`（三步程序 + 五项执行门）

## 一、目的与假设（明写预测，防事后解释）

| 编号 | 假设 | 预登记预测 |
|---|---|---|
| H1 | **Gen5 加大谷现象**（Gen4 起谷被环境抑制） | Gen5×prod 出现探针 `decode<60`（=历史 400MiB 3/3 复现） |
| H2 | ~~sym3 修复/优化了谷~~ | **本假设撤回**：Gen4 下 prod 亦未入谷，无对比基础（TELE 指正：这不是"修复"，谷根本没出现）；正确表述=回落幅度差异 |
| H3 | 回落幅度存在件差异 | Gen5 下 sym3 的两位数(<100)比例仍低于 prod |

## 二、设计（单变量 + ABBA 交换顺序）

- **单变量**：PCIe Gen4 → **Gen5**（其余全同：件、池 49152、剂量 400MiB、HoldSec 210、探针 12s×3 轮、参数一字不差）
- **顺序**：Gen4 批 = sym3 → prod；**Gen5 批 = prod → sym3（ABBA 反序）**，控顺序/时窗
- 2×2 全表：Gen4×sym3 ✅ / Gen4×prod ✅ / Gen5×prod ⬜ / Gen5×sym3 ⬜

## 三、判据与执行门（缺一不开跑）

1. **贴边达成**：施压期 `memory.free` **直采**（禁"总量−used"推算）< **381 MiB**（=400MB）；未达成 ⇒ 本批判"测量失败"，不进结论
2. **谷判定**：探针口径 `decode<60`（与历史"3/3"同口径；禁与长请求口径混比）
3. **回落判定**：探针 `decode<100` 比例（件差异指标）
4. **双向闭环**：释放 30s 后探针 `decode≥100` 且回升
5. **落盘**：每拍 free 直采 + clk/pow/util + 引擎日志 host% + reqlog + `pcie_gen` 字段
6. **两脚本**：`launch_engine.ps1 -Engine sym|prod -Tag g5` / `retest_run.ps1 -Engine sym|prod -Tag g5`（已修：JSON 转义、vram_hold 自动 spawn 台账、样本带 pcie_gen）

## 四、停止条件（WHEA）

- 回切 Gen5 后盯 WHEA（系统事件查看器）；**复发即停**：降回 Gen4 + 记录停点。旁证：近 6h WHEA 仅 1 条（昨晚 22:40），整体平静，但 Gen5 正是当初风暴档位

## 五、不做的事

- 不加剂量（保持 400MiB 单变量）
- 不混口径（全程探针口径）
- 不在贴边未达成时解读谷结果
- 不跑长请求替代探针
