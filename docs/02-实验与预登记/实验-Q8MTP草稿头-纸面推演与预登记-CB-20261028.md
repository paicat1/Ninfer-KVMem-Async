- 日期：2026-10-28（CB 起草；零机时纸面推演 + 后续单发 smoke）
- 性质：**纸面推演已完，实验为最低成本探查**（单发 smoke + 一轮标准轮，~10 min）
- 状态：**草稿，待 TELE / 用户审**；优先级**低于 KV 精度主线**（v5.1 已放行，B/C/C-ctrl 正在跑）
- 不自判收益：结论交 TELE 对账

---

## 〇、纸面结论先行

1. **Q8 草稿头的好处只有一条**：接受率 ↑ → decode ↑，**且对输出质量中性**（草稿由主模型验证/拒绝，不污染最终分布）。
2. **它不解决语义漂移**——那是 KV 精度 / 主权重的事，草稿头精度与之无关。
3. **净收益存疑、大概率为负**：在 DSH 45–73K **超池生产工况**下，+202.5 MiB 换来的池缩小，很可能吃掉接受率那点增益。
4. 一条硬反证：**接受率的主控是 KV 精度，不是草稿头**（见 §四）。

---

## 一、关键澄清：两个"Q8"不是一回事（最重要，防误判）

| 版本 | 体积 | 信息量 | 来源 |
|---|---|---|---|
| **P1 的 `q8_0`** | 451,215,360 B | **仍是 4-bit 信息** | `recode_mtp.py` 把原件 `q4_0` **位级无损**装进 8-bit 容器（nibble→`int8(nibble−8)`，零浮点、零重量化） |
| **官方 Q8MTP 版的 MTP 头** | 451,215,360 B（字节数相同） | **真 8-bit** | v12 原文："官方 Q8MTP 版…**真 8-bit**"；官方重新量化的 8-bit 权重 |
| **现役 `iq4_nl`** | 238,878,720 B | 4.5 bpw | 自转，等长 Δ0、省 212 MB |

> 档案教训原文（v12 §6.1）：「我们的 q8_0 对 q4_0 无损，但对原始权重是有损的（保留了 4-bit 损失）。**换格式能省显存的前提是"更小的 bpw"，更小必然有损**」，本次量化为 **误差 8.4–9.1% / SNR 21.5 dB**。
> ⇒ **若误以为"P1 已经做过 q8 了"，是错觉——P1 的 q8_0 没有任何精度增益。真 8-bit 只有官方 Q8MTP 版。**

---

## 二、收益侧（机制 + 上限）

- **机制**（roadB §5.6 原文）：「MTP 是草稿头，精度损失**不影响主模型输出分布**（投机解码由主模型验证/拒绝），但会**降低接受率**」。
- ⇒ Q8 草稿头 = **纯速度杠杆 + 输出零污染**；这是它相对"KV 精度升级"的**唯一优势**（KV 精度既改速度又改输出）。

**上限算术**（K=4，`--draft-tokens 4`）：每步期望接受 token 数 = \((1-\alpha^5)/(1-\alpha)\)

| 接受率 α | tokens/步 | vs 基准(0.918) |
|---|---|---|
| 0.918（A 档实测） | 4.25 | 基准 |
| 0.95 | 4.52 | **+6.4%** |
| 0.99 | 4.90 | **+15.3%** |
| 1.00（理论顶） | 5.00 | **+17.6%** |

⇒ **草稿头做到完美，上限也只有 +17.6%**；4-bit→8-bit 现实落在 **+5~8% decode**（还要扣 draft+verify 步进开销）。

---

## 三、代价侧：+202.5 MiB → 池折算

`+212,336,640 B = +202.5 MiB`

| KV dtype | 字节/token | 池损失 |
|---|---|---|
| rk2v4-e8 | 13.0 KiB | **−16.0K** |
| nvfp4 | ~15.1 KiB | **−13.7K** |
| rk8v4 | ~45.5 KiB | **−4.6K** |

---

## 四、⚠️ 硬反证：接受率的主控是 KV，不是草稿头

**同一个 `iq4_nl` 草稿头**，只换 KV dtype（2026-10-27 冷启实测）：

| 档 | KV dtype | 池 | r1 接受率 |
|---|---|---|---|
| A | rk2v4-e8 | 65,536 | **91.8%**（ON 1827/1989、OFF 1732/1889） |
| C | **rk8v4** | 58,368 | **99.4%**（ON 1865/1877） |

⇒ 接受率是被 **KV 精度**拉起来的。**推论（交叉结论）**：

- 生产留 **rk2v4**（91.8%）⇒ Q8 草稿头理论空间大（+8pt → 约 +15% tokens/步），但**池代价最大（−16.0K）**；
- 生产升 **rk8v4**（99.4%）⇒ Q8 草稿头**几乎无空间（+0.6pt ≈ 0）**，却仍要付 202.5 MiB ⇒ **纯亏**。

**收益最大的地方代价最大，收益最小的地方代价最小。**

## 五、预登记设计

### 5.1 目的
测"**官方真 8-bit 草稿头**"在**新平台**（+707 MiB 余量）能否带来 **≥3pt 的接受率增益**，并判断是否值得用 202.5 MiB 去换。

### 5.2 件与加工路径（零训练，只加工）
- 候选 A（最省事）：**官方 Q8MTP 件** `…Q2LynnStyle-Q8MTP.ninfer`（12.84 GiB；components = text + mtp + vision；MTP 头 `gguf_q8_0` ×5）。旧平台三度起服失败（缺 **139–200 MiB**），新平台应可起。
- 候选 B（推荐，避免 +0.5 GB 文件膨胀）：用 `recode_mtp.py` / `graft_vision.py` 思路**抽取官方 MTP 头**嫁接到现役件 `.mtp-iq4nl.vision.ninfer`，得到"**真 Q8 草稿头 + 我们已嫁接的视觉**"。
- **唯一变量 = MTP 草稿头精度**（主权重 Q2LynnStyle、KV dtype、池、graph、depth 全部保持不变）。

### 5.3 协议（沿用 v5.1 无 warm 规范）
- **冷启直发，禁止 45KB warm**（warm 已证为不对称扰动）。
- 负载：a2gate `--filler-kb 300 --max-tokens 2000 --rounds 2`（与 A 档同口径）。
- 臂：`NINFER_ASYNC_DEMOTE=1`（ON，生产形态）。
- 池：优先 **rk2v4 档**探（因接受率空间最大）；若时间允许再探 rk8v4 档。

### 5.4 步骤
1. **smoke**：起服 + READY + 一轮 45KB（确认 dtype×新硬件组合可起）；
2. **停服**；
3. **冷启** → 300KB 标准轮 ×1（rounds 2）；
4. 记录：接受率 / decode / `free` 直采 / 池 / `finish_reason`。

### 5.5 判据（先写死，再跑）

| 项 | 判据 |
|---|---|
| **主判据（成立）** | r1 接受率相对 A 档基线 **≥ +3.0 个百分点**（91.8% → ≥94.8%）⇒ 草稿头增益成立 |
| **否决项 1（不划算）** | 若为容纳 Q8 头需把池降到**显著加深超池**（rk2v4 池 < 45K，或 rk8v4 池 < 53K 致 DSH 覆盖明显变差）⇒ 判**不划算**，无论接受率增益多少 |
| **否决项 2** | smoke 起服失败（即便新平台仍缺显存）⇒ 直接归档"硬件仍不容" |
| **记录项** | 接受率（分子 `draft_n_accepted` / 分母 `draft_n`，绑 `docs/01-构建与发布/遥测口径对齐-#153-20261020.md`）、decode、`free` 直采、池、`finish_reason`（三分辨：stop/正常触顶/超池截断） |

### 5.6 对照基准
- **A 档冷启基线**：ON r1 decode 320.4 / 接受 91.8%；OFF r1 243.4 / 91.7%（2026-10-27，S13 322A972D，rk2v4 @65,536，无 warm）。

## 六、边界与"不做"

- **不做**：不训练、不重新量化主权重、不改引擎源码、不构造工况、不引入新引擎 binary。
- 边界：官方 Q8MTP 件含官方 vision（333 张量 / 282 MiB 级），不传 `--vision` 不加载；**本预登记不测视觉**。
- 已知未知：iq4_nl → 真 8-bit 的**接受率增益无任何实测**（P1 的 q8_0 因信息量不变而不可用于推断）⇒ 必须实测，不得引用档案推算。

## 七、成本与执行序

- 机时：**~10 min**（smoke ~2 min + 停服 + 冷启标准轮 ~5 min + 记录）。可挂在 KV 精度主线的空档执行。
- 执行序：
  1. 本预登记经 TELE / 用户审；
  2. 备件（优先候选 B 加工路径，或直接用官方件）；
