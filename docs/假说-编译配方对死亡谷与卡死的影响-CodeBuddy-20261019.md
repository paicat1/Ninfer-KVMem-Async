# 假说：编译配方对死亡谷与卡死的影响

> 性质：**假说文档（未验证）**——判据先于数据（§5 预登记）。作者：办公室侧（CodeBuddy）。日期：2026-10-19。
> 证据基础：`docs/工程史-死亡谷根因排查与确定-CB-20261017.md` 附录 D 项判决 / Gen5 判决（家里线 10-18~19 实测）；本文不引入新数据，只对已有数据提出机制假说与可证伪实验。

## 0. 一句话假说

**链接布局（而非符号本身）决定驱动分页路径在显存压力下的结局——有的布局"慢而收敛"（深谷后自愈），有的布局"走进循环等待"（卡死）；死亡谷本身与编译配方无关（三个编译件全部入谷），编译差异裁决的是"卡死"这一症状。**

## 1. 证据基础（全部来自家里线实测，本文不新增数据）

D 项判决的三角矩阵（同源码、三种链接产物、Gen5、同外压协议）：

| 编译件 | 符号 | 谷（深谷但走得完） | 卡死（永不返回） |
|---|---|---|---|
| S13（旧件） | 无 | 有 | **有** |
| sym3（重编） | 有（/Zi+/DEBUG） | 有 | 无 |
| offi（新编） | 有（同工具链） | 有 | 无 |

辅证：谷的机制已定位到源码级——外部显存压力（≥400 MiB 必中 / ~150 MiB 约 1/5）→ MTP target/verify 段 → **cudaGraphLaunch 阻塞 497 ms 中位 / 2.23 s 最大**（占 CUDA API 时间 94.5%），GPU 内核几乎不执行（0.007 s / 40 s 窗）；自然谷与外压谷同源（自然谷时外部占用 642 MB 常驻 + 自由显存贴边）。

## 2. "不同的编译"实际改变了什么（三层，符号最无辜）

| 层 | 内容 | 对执行的影响 |
|---|---|---|
| ① 符号元数据 | PDB / PE debug directory | **无**——纯调试信息，不进入任何执行路径 |
| ② PE 文件布局 | .debug 节出现、节顺序/大小/对齐/填充、导入表排布 | 间接——决定加载后的模块布局 |
| ③ 运行时虚拟地址布局 | ASLR 基址下模块/节/堆栈的实际落位、与进程内其他 Allocation 的邻接关系 | **直接**——构成驱动显存管理决策的输入 |

**推论 1**：D 项判决的准确读法是"**布局敏感**"，不是"符号敏感"——/DEBUG 顺手改变了 ②③，符号只是搭车出现的指标。由此，"以后都带符号编译"只是换了一种布局的权宜之计，不是根治。

## 3. 谷与卡死是两个问题（本文的核心区分）

| | 谷（深谷但走得完） | 卡死（永不返回） |
|---|---|---|
| 三个编译件中的分布 | **全部** | 仅特定布局（S13） |
| 触发 | 外部显存压力（剂量-概率） | 同源码同压力下，仅特定布局 |
| 驱动内结局 | cudaGraphLaunch 阻塞 0.5-2.2 s 后**返回** | 同一路径上**永不返回** |
| 与编译配方的关系 | 无关 | 相关（布局维度） |

⇒ 编译配方裁决的是卡死，不是谷。**任何"编译治好了死亡谷"的表述都不成立**——三件在相同外压下全部深谷。

## 4. 机制假说：驱动分页路径的"布局依赖"

背景链：外压 → 显存碎片/紧缩需求 → 图提交触发 demand-paging（WDDM make-resident/eviction）→ cudaGraphLaunch 阻塞等待分页完成。在这条链上，布局可以从三个位置改变结局：

**假说 A：分页队列的循环等待（卡死的首选解释）**
make-resident 队列中的多个 Allocation 存在相互依赖（A 的落位要等 B 被逐出，B 又被 C 的迁移 pin 住）。**依赖图的形态由 Allocation 的地址排布与大小决定**——布局差异 → 依赖图不同 → 某些布局存在循环等待（死锁 = 卡死），另一些只是长链（慢 = 谷后收敛返回）。
与观测的吻合度：解释"外压是触发器"（无外压时分页队列短，循环等待形成不了）+ 解释"同源码不同件行为分化"。

**假说 B：内核态重试逻辑的布局触发**
驱动的紧缩/迁移重试在特定碎片形态下进入无效重试循环（每次重试复现同样的碎片形态）。布局决定碎片形态。

**假说 C：与外压进程的地址邻接效应**
外压进程的 Allocation 与引擎 Allocation 的邻接关系影响驱动的搬移/压缩选择——布局差异 → 邻接差异 → 压力下路径分化。

三个假说共享同一前提：**驱动内部决策对用户态内存布局有依赖**——这本身可由 §5 的实验间接验证。

## 5. 判决实验设计（判据先于数据；预登记）

**目标：把"符号"与"布局"两个被 /DEBUG 绑定的变量拆开。**

| 实验 | 构建方式 | 判据（数据前写死） |
|---|---|---|
| **E1 布局控制** | 带符号但强制不同布局（/ALIGN 调整、/DYNAMICBASE:NO、节重排） | 同源码同外压：若某布局复现卡死 ⇒ 布局敏感成立、符号洗清；若全部不卡 ⇒ debug directory 本身有作用（进入 §7 的怪分支） |
| **E2 符号分量** | 无符号但复刻 sym3 的节排布（/ORDER、/ALIGN） | 与 E1 互补，双向锁定 |
| **E3 DEBUG 子开关** | /DEBUG:FASTLINK vs /DEBUG:FULL vs 仅 /Zi | FASTLINK 不改变 PE 布局——若 FASTLINK 即消除卡死 ⇒ 回到"诊断元数据影响"分支（需重新审视全部假说） |
| **E4 布局普查** | `dumpbin /headers` 三件节表/对齐/重定位/入口逐项对比 | 量化布局差异落点，为 E1-E3 提供机制锚点 |

**取证增强**：带符号件复现深谷时抓 **DxgKrnl ETW**（分页队列 trace）——直接观测谷窗内 make-resident 队列的行为与重试结构；卡死复现（无符号件）抓内核 dump 看分页队列的等待图。
**成本估算**：E1-E3 各一次构建 + 一次外压协议（约 2 分钟/轮）≈ 2-3 小时机时；E4 纯静态。

## 6. 对修法的含义（分层）

1. **短期**：带符号构建（offi）作为卡死规避手段（已落地，转正候选）——但要明确其性质是**布局彩票**，非根治；防复发靠 §5 的机制定位而非运气；
2. **中期**：E1-E3 定位到具体布局成分后，把防卡死的链接选项固化为**构建门禁**（结构性规则，进 CI/构建脚本检查清单）；
3. **上游/驱动侧**：谷与卡死共享同一入口（图提交触发分页），且双症状可用同一外压协议切换（外压 + 无符号布局 = 卡死；外压 + 任意布局 = 深谷）——**双症状复现包**对驱动厂商的诊断价值高于单一谷症状；
4. **文档纪律**：所有"编译修复了卡死"的表述应改写为"**带符号布局未复现卡死**"——除非 E1-E3 完成机制归因。

## 7. 诚实边界与可证伪性

- 本文全部为**假说**：驱动内部分页/提交路径是黑盒，A/B/C 三个假说当前无法直接观测，只能经由 §5 的行为实验间接区分；
- 样本量：D 项判决的卡死/不卡死判定基于有限轮次（外压协议轮数见工程史）——E1-E3 应每格 ≥3 轮再下结论；
- 被证伪的出口：若 E1-E3 显示卡死与布局无关、且 E3 显示 FASTLINK（不改布局）同样消除卡死——则"符号/diagnostic 元数据影响执行"的怪分支成立，本文全部假写作废，需从头审视（该分支概率低，但预登记在案）；
- 与既有结论的相容性：本文不改变"谷 = 图提交路径驱动阻塞"的定位（Gen5 域内），只对"卡死"这一症状追加布局维度假说；Gen4/Gen5 的 PCIe 代数维度独立存在，本文不涉及。

## 8. 结语

D 项判决把"同源码、不同编译、不同结局"的事实摆上了台面；本文把它从"符号玄学"拆成"布局机制"，并给出可证伪的判决实验。**符号是目击者，布局才是嫌疑人**——E1-E3 一次开庭，即可定案。
