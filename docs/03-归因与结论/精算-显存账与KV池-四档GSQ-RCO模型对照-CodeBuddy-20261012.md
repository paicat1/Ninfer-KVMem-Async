## 0. 口径与三个硬锚（一切计算的基石）

**锚 1 · 页账（最精确）**：`1 页 = 64 token`；`rk2v4-e8 下 1 页 ≈ 0.83 MiB`
- 构建史页数-容量对全部 = 64 tok/页：8,192/128 页、20,480/320 页、32,768/512 页、40,960/640 页、55,296/864 页、65,536/1024 页、**81,920/1280 页（2026-10-13 实测成功）**
- ⇒ **池预算双口径（v3.0 起为全文主口径）**：
  - **贴边口径 = 1,062 MiB**（1,280 页 × 0.83 MiB = 81,920 实测档；98,304 被拒 -134 MiB ⇒ 贴边抖动带 ±130 MiB）
  - **稳定口径 = 956 MiB**（贴边 ×0.9，留桌面波动边际）
  - （历史口径 864 页 ≈ 717 MiB = 55,296 时代，v2 各表所用，v3 仅作对照）
- 每 token ≈ 13.0-13.3 KiB（理论构型 13.0 / 实测页账 13.3）

**锚 2 · 标定差**：55,296 → 65,536（+160 页）恰需 +128 MiB（`--cuda-graph-allowance-mib 128` 补缺起服）
- 160 页 × 0.83 MiB = 132.8 MiB ≈ 128 MiB ✓（±3%）

**锚 3 · 理论构型**：16 全注意力层（64 层 4:1 混合）× 8 KV heads × 128 head_dim
- rk2v4-e8 = K 2bit(256B) + V 4bit(512B) + scales/e8(64B) = 832 B/层 → ×16 = **13.0 KiB/token** ✓
- k8v4 同法 = 1600 B/层 = 25.0 KiB/token —— 与教程"每 token ≈ 25 KiB（k8v4）"逐字吻合 ✓

**锚 4 · 权重实测**：当前上卡权重 = **12.30 GiB**
- README 显存账："权重 12.3 GiB + 高速池/工作区 1.9 GiB + 视觉，free 490 MiB"
- 构建史实测：Q8MTP 版 `loading weights | 12.5 GiB`（10-10 00:32）− iq4_nl 头省 212 MB ≈ 12.29 GiB ✓ 双源吻合

**当前池标定（本库实测）**：40,960 稳定 → **51,200 稳定** → **55,296 贴边**（缺 17-50 MiB 随桌面波动）→ **65,536 实测成功**（需 graph128 + 净桌面 ≤~1.0 GiB）→ **81,920 实测成功（2026-10-13；98,304 被拒 -134 MiB）**
- 用户"卡在 55K 左右" = 55,296 贴边口径（历史）；**v3.0 主口径 = 81,920（rk2v4 实测天花板）**
- **性能基线（用户 2026-10-14 盘点）**：rk2v4 + 大池工况下 **极值 400+ tok/s**（构建史最高记录 463.9）/ **连续 1 小时综合平均 220 tok/s**——后续所有精度/池对照以此为归零基准
- **平台现状（2026-10-15 更新）**：**生产已切至 IQ3_S（Swift 1.5）+ rk8v4 @ 65,536**（深 60K 143.7 tok/s、接受率 64%、free 727.9 MiB）；本文档"当前模型（Q2Lynn）"各表自本日起为**对照基准**定位。**请求线实测锚（同日）**：**中位 56,440 / 最大 96,430**（90 条真实会话、72 条 >40K、缓存命中 ~100%）——旧"45-73K"为估算口径，v3.3 起全面替换。

## 3. 能力对照（换过去能力怎么变）

**3.1 底座差异（最大变量）**：Swift-1.5 = Qwen3.8-27B 的"推理高效型"微调（UkisAI）——**与现役 Coder390-EfficientThink 同向，但微调方不同**。
- 官方 BF16 基准（ukisai.com）：比 Qwen3.8-27B 少 **58.5%** 思考 token（中位），8 项基准 6 项不降反升：
  - **LiveCodeBench v6 76.76 → 81.71（+4.95）** · **Terminal-Bench 2.1 69.21 → 72.13（+2.92）** ← 编码/agentic 向增强（正是本线用途区）
  - GPQA +0.31 · C-Eval +0.92；略降：ERQA −2.05 · AIME −2.67 · HMMT −2.00 · IFBench −1.46
- 训练路径：RL + 同策略蒸馏，聚焦**长时程 agent 与编码任务**（与 DSH agentic 用途吻合）。
- ⇒ **换底座 ≠ 降级**，是"换任务画像"：编码向大概率持平/更强，纯推理向略弱（参考量级：1-3 分）。

**3.2 量化损失（GSQ-RCO 方法 + 官方 KLD 表，v2 更新）**：
- GSQ（Gumbel-Softmax 学习网格+scale）+ RCO（黎曼约束逐张量比特分配），2026 新方法；实现路径：复用 ISTA-DASLab 的逐张量分配 + Swift V1MIX importance matrix 精炼。
- **ukisai 源 GGUF 仓的官方 KLD 表**（相对 Swift-1.5 BF16，512-token 口径；code 域 = CodeParrot，散文 = C4）：

| 档 | 开发集 KLD | code 域 KLD | C4 KLD | 中文 KLD |
|---|---:|---:|---:|---:|
| IQ2_XS | 0.189979 | 0.120884 | 0.161594 | 0.207063 |

- 参照系：KLD <0.05 ≈ 接近无损；IQ3_S（code 0.035）量化损伤确实小；IQ2_XS（0.121）已偏大。
- ⚠️ 官方自注：512-token 测试**不能说明长上下文质量**；且 ukisai 精炼版与 ISTA 对照并非全面更优（数学文本 KLD 高 4.9-7.7%、IQ3_S 在 7 域中 5 个高于 ISTA 对照）；这是分布指标**非任务分**。
- 与 ISTA 官方数字（经引述）：2.75bpw 档零样本综合均分 **75.70 vs BF16 74.34**；同体积对 Unsloth UD-IQ2_S：**AIME25 +10.0 / GPQA +8.6 / LCB +4.6**。

**3.3 与当前 Q2LynnStyle 的关系（v2 修正）**：
- **Q2LynnStyle 真实构成（Merkyor 官方）**：BPW = **3.89**（"LynnStyle" = 混合精度风格、最低下探到 Q2，**非全模型 2bit**）。LynnStyle 全谱：Q2 3.89 / Q3 5.07 / Q4 5.75 / Q6_K 6.79 / Q8_0 8.51。
- 本库鉴定（804 对象）：真 Q2 级张量仅 **23 个**；主体为 iq3_s(144) + iq4_xs(76) + q4_k(67) + iq3_xxs(26) + iq2_s(21) 混合；bf16/fp32 高精度小张量 456 个；MTP 头 5×q4_0。
- **IQ 四档换算 BPW（÷27.32B 参数）**：IQ2_XS **2.62** / IQ2_S **2.71** / IQ3_XXS **3.12** / IQ3_S **3.62** —— **四档全部低于 Q2Lynn 的 3.89**。
- **Q2Lynn 任务分（Merkyor 官方，llama.cpp 口径）**：GPQA **177/198（= FP8 原版）** · LCB **90/100（> FP8 原版 83）** · MMLU 433/500（-2.5%）。
- **结论修正**：IQ3_S 量化损伤小（code KLD 0.035）为真，但**"质量更优"不成立**——其 bpw 低于现役 Q2Lynn；两边量化损失都不大，差异主因在**底座微调**（Swift-1.5 vs Coder390）+ 方法（GSQ-RCO vs imatrix+Lynn 配方）——须本机 A/B。

## 6. 全矩阵：4 模型 × 6 精度 → 池容量（token，贴边口径）【v3.2 实测口径重算】

## 7. 池目标函数的修正：异步页流水之后，池不再是"容量门槛"（v2 确立；v3.0 精细化见 §7.6 / §7.7）

**背景**：v2 异步页流水（`patches/ledger42_v2_async_demote.patch`）使 demote/restore 与 decode 流水并行——**物理池从"容量门槛"降级为"搬运频率旋钮"**。本库实测：74.4K 深超池（host 99%）decode 仍 **114.4 tok/s**；深谷可自愈爬出；多轮对话可用（v2 前多轮必死）。⇒ **不必追 262K 全驻留**。

### 7.3 结论

- **不换模型的同预算升级三选一（v3.2 口径）**：`81.9K + rk2v4-e8`（现状，最快）/ **`59.1K + nvfp4`（精度 +1 档，池仍超工作集 41%——需过逐字门）** / `41.7K + rk8v4`（贴工作集线——不推荐，见 §7.7）。
- ⚠️ **谷视角修正（v2.1）→ 放行 + 两条硬约束（v2.2 更新）**：后两档的隐性谷代价为现状的 8-13 倍（demote 量 ∝ (上下文−池) × 每token字节），但 **v2.1 默认 depth=1 已移除灾难性放大项（R2 §三）⇒ 不再"暂缓"**。新增两条实机实证的硬约束：
  - **① 预算线约束（v3.2 口径）**：缩池换精度必须留在"该精度的预算线"内——当前模型 `rk8v4` ≤ **41,664 贴边 / 37,504 稳定**；`nvfp4` ≤ **59,072 / 53,184**（v2 时代的 28,800/26,624 为 717 MiB 旧预算）。历史越线警训仍有效（32,768@rk8v4 越 ≈97 MiB → 页账故障 + HTTP 500）——**取稳定档、不追贴边**；
  - **② prompt 约束**：池 ≥ 预期最大 prompt（DSH agentic 会话 **实测中位 56,440 / 最大 96,430**——v3.3 更新；旧口径 45-73K 作废）。
  两条约束的算术（v3.0 复核）：现模型上"49.6K prompt + k8v4"物理不可行（需 ≈1,231 MiB > 贴边 1,062，缺口 ≈170 MiB；rk2v4 只需 642 MiB）⇒ **要兼得只能换更小的模型档**（§7 换模型路线，§7.7 专表）。
- **换模型最优组合（64K 池固定）**：**IQ3_S + 61.6K@k8v4**（全面小升，最保守）；**IQ3_XXS + 64K + Q8**（池翻倍 + KV 升 2.62×；64K@Q8 需 ≈2,181 MiB，仅 IQ3_XXS 及以上档可装）；**IQ2_S + 64K + bf16**（KV 天花板，权重降至 2.71bpw）。⚠️ 同样受 §7.4 谷负担公式约束（大池是它们的成立前提）。
- **待测汇率**：权重 bpw vs KV 档，谁更伤代码质量——先做 KV A/B，再定换模型方向。
- **v3.0 口径更新**：本节组合按旧预算（717 MiB）成文；按新锚（1,062 MiB）重算的最优工作点见 **§7.7 专表**。

### 7.4 池的第三重身份：死亡谷的缓解旋钮（v2.1 追加）

> 缘起：用户提出"池大是否也能配合异步机制，缓解死亡谷的深度/概率/延续时间"——机制分析成立，且反向修正了 §7.3 的推荐。

**谷的机理链（req#61 解剖，构建史 §三·十九）**：
多轮堆积 → 页漂移深 → demote 需求暴增 + copy 慢（avg 11.5 / max 33.68 ms/批，PCIe 竞争）
→ 页操作总耗时超步窗口（host 200-318%）→ decode 步几乎全在等页 → demote 消化完后自愈。

**⚠️ 机理更新（v2.2 · 2026-10-13，I1/I2 深挖）**：
- **demote / ring / restore 三路已排除**：环内五段亚毫秒级、STALL=0、回收零等待；深谷时 `mask=0 / SELECT=32 / retrieve=25`（近乎静默）而 host 94-148%、GPU 99%、**每 token ≈3 s host 工作** ⇒ 本谷是"**静默自旋**"，**瓶颈在环外未计量路径**（推翻"谷=demote 风暴"的旧表述）；
- **触发与 host 页库规模相关**：谷起点紧随页库 1.42→1.49 GB 跳变（重填新增页）——"页库规模相关成本"嫌疑（下一刀：I3b 步级仪表）；
- ⇒ §7.4 核心公式**方向不变**（池大 → 超池量小 → 页库/搬运成本低），但"谷负担"的构成扩展为"页库规模相关成本"。

**⚠️ 机理更新二（v2.3 · 2026-10-14，夜间自动迭代）**：
- **GPU 侧自旋指纹**：谷期 util 99.8-100% + SM 满频 2,910 MHz + pmon 锁定 ninfer-serve（87-99%），但**显存控制器仅 2.6-9%**、功耗 63-98 W（健康 129-217 W/64%）；单轮墙钟 400-1,019 ms = **1107 节点 × ~24 µs/节点**（健康 27-32 ms）⇒ 自旋在**图内节点间隙**；已排除提交/驱动、降频、外部进程、带宽拉爆；
- **谷 = 时间现象，非 token 现象（A2 lossless gate 通过）**：同 prompt 池内与首次超池的输出 **sha 逐字相同**——超池本身不改变输出，谷是**时段性**降速；
- **机器级粘性**：谷跨引擎重启存活 ≥4.5 小时（非进程状态）；三次自愈（23:45 / 01:06 / ~05:40）+ 两次来袭，触发源未明（守望者已上线抓它）。

**池的作用（四个环节全单调缓解）**：

| 环节 | 池大的效果 |
|---|---|
| ① 漂移起点 | `depth = pool − working_set`（tancau 作者级公式）→ 触发更晚（实测：64K 比 51K 多撑 ~8 轮） |
| ② 需求速率 | demote 量 = 上下文 − 池 → 池大 → 需求速率低 → **谷概率↓** |
| ③ 拖死程度 | 积压量 ∝ 单次需求批次 → 池大 → 积压小 → **谷深度↓** |
| ④ 自愈时间 | 谷时长 ≈ 积压 ÷ 消化速率 → **延续时间↓** |

**核心公式**：`谷负担 ∝ (上下文 − 池tokens) × 每token字节`（池与 KV 精度在此式中是乘法关系）。

**隐性谷代价（以 60K 上下文为场景）**：

| 组合 | demote 量 | 谷负担 | 相对现状 |
|---|---:|---:|---:|
| **现状：55.3K + rk2v4-e8** | 4.7K tok × 13 KiB | **61 MiB** | 1.0× |
| 41.3K + rk4v4-e8（同预算） | 18.7K × 17.4 | 325 MiB | 5.3× |
| 32K + rk4v4-e8 | 28K × 17.4 | 487 MiB | 8.0× |
| 28.8K + k8v4 | 31.2K × 25 | 780 MiB | 12.8× |
| **v3.2 现役：81.9K + rk2v4-e8** | 0（60K 上下文全驻留） | **0** | — |

- 单轮活跃集（窗口 32,768 + sink 5,120 ≈ 38K）——池 ≥ ~40K 后单轮型谷饱和；

### 7.6 池的收益-成本曲线与"甜点区"（v3.0 新增 · 机制综合）

**需求结构（三条线）**：工作集线 = **~42K**（sink 5,120 + window 32,768 + 检索召回 ~4K，decode 每步实际读的量）· 请求线 = **实测中位 56,440 / 最大 96,430**（90 条真实会话；v3.3 更新，旧"45-73K"为估算口径）· 逻辑上限 = 262,144。

**收益三段（池 vs 需求）**：

| 区间 | 判据 | 行为 |
|---|---|---|
| I. 池 < 工作集（<~42K） | 每步都在搬运 | 最差区——全靠异步流水硬扛，击穿即掉速 |
| II. 工作集 ≤ 池 < 请求线中位（42-56K） | 覆盖一半会话的常规轮次零超池 | **甜点区（保守段）**——搬运只在多轮堆积时发生 |
| II′. 请求线中位 ≤ 池 < 请求线最大（56-96K） | 覆盖大多数会话 | **甜点区（优选段）——生产档 65,536 即此段** |
| III. 池 ≥ 请求线最大（>96K） | 只防极深堆积/尾部会话 | 边际收益骤降（实测：64K vs 51K 仅多撑 ~8 轮） |

**成本三项（为什么"不是越大越好"）**：
1. **机会成本（最硬）**：16 GB 零和——每 1 GiB 给池 = 少 1 GiB 给 KV 精度/权重档，而精度是"每一轮都在付"的质量；
2. **贴边风险（非线性）**：98,304 被拒 -134 MiB；越线先例（32,768@k8v4 越 ~97 MiB → 页账故障 + HTTP 500）；
3. **页库规模成本（嫌疑，方向待判）**：谷起点紧随页库 1.42→1.49 GB 跳变（§7.4 v2.2）——若与池正相关，则存在真·内部最优点。

**异步流水的"隐藏预算"（速度的第四变量）**：v2 单槽 = 每步最多一批（8 页）在飞；正常期 copy 1-3 ms ≪ 步窗 27-32 ms（完全隐藏，74.4K 深超池 decode 114.4 tok/s 为证）；谷期 copy 11.5-33.7 ms ≈ 步窗（暴露）。**KV 精度 ×1.34/×1.92（nvfp4/k8v4）同比放大单批字节 → 直接压缩击穿余量。**

**KV 精度耦合恒等式（"精度升档后最佳池会变"的精确形式）**：设 C = 上下文 token、c = 每 token 字节、B_pool = 池字节：

```
超池 token 数 = C − B_pool / c        （逻辑口径 → 谷负担按此计）
超池字节量   = C × c − B_pool         （物理口径 → 搬运/PCIe 按此计）
```

c 升档（k8v4 = 1.92× rk2v4）→ 同 B_pool 下**两个口径同时恶化**（超池起始点提前 48% + 字节量增长，无对冲）；要维持同谷负担须 B_pool ×1.92。⇒ **最优"池 token 数"变小、最优"池字节数"变大**（同一事实的两面）。

**"完美配置"的方向**：浅池（覆盖工作集 + 余量）+ 深流水（v2.1"在飞页计入空闲裁决"修法待复核）+ 高 KV 精度——池从"平衡木"退场，精度与权重成为主角。理想态：**池不大，而是"不需要大"**。

### 7.7 最佳池容量：k8v4 / nvfp4 专表（v3.0 新增 · 目标问题直接答案）

**口径**：贴边 = 1,062 MiB + 模型省下字节；稳定 = ×0.9（工程推荐）。判据：工作集线 42K（decode 零搬运）/ **请求线实测：中位 56,440（覆盖大多数会话）· 最大 96,430（尾部会话）**——v3.3 更新。

| 模型（省下字节） | **rk8v4 贴边 / 稳定** | **nvfp4 贴边 / 稳定** | **Q8 贴边 / 稳定** | 判决 |
|---|---:|---:|---:|---|
| 当前 Q2Lynn（0） | 41.7K / 37.5K（⚠️贴线） | **59.1K / 53.2K** | 32.2K / 29.0K（✗ < 工作集） | 仅 nvfp4 可行 |
| IQ3_S（+0.80） | 73.9K / **69.6K** | 104.6K / 98.8K | 57.0K / 53.8K | rk8v4 = **覆盖中位（69.6K > 56.4K ✓）、盖不住最大**（96.4K）；nvfp4 98.8K ≥ 最大 ✓；Q8 覆盖中位 |
| IQ3_XXS（+2.36） | 136.6K / **132.4K** | 193.6K / 187.7K | **105.5K / 102.3K** | 三档全可行 |
| IQ2_S（+3.67） | 189.2K / 185.1K | **262K 全驻留**（余 0.10 GiB / 压线） | 146.2K / 143.0K | nvfp4 全驻留 |

**推荐工作点（v3.2 · 附质量门排序）**：
- **rk8v4 目标（8bit 族首选：第三方实测质量、速度曲线双优于 k8v4）**：最低成本 = **IQ3_S + 69.6K（覆盖中位、不覆盖最大——现生产档 65,536 即此段）**；**完整覆盖（≥96.4K）= IQ3_XXS + 132.4K**；当前模型 **✗ 不可行**（41.7K 贴线 = 漂移从第一步开始）。

- **Q8 / int8 目标（质量无损档，PPL ≈ bf16）**：均衡 = **IQ3_XXS + 102.3K（≥ 最大请求线 96.4K ✓）**；质量极 = **IQ2_XS + 151.9K**（≈逻辑上限 60%）；当前模型 **✗ 不可行**（29.0K < 工作集 42K）；IQ3_S + 53.8K 仅适合中短会话。★ **待复核**：构建史 §48 记"IQ3_S 上 int8 可到 61,440"（>本表贴边 57.0K，+7.8%，处于 ±5-8% 带宽边沿）——若复测坐实，Q8 页字节（§1 = 33.0 KiB）或需下调至 ~30.6 KiB。

**速度预期（先记账，测时对照 220 tok/s 基线）**——稳态 decode 的 KV 读只发生在工作集（42K × 每 token 字节）：

| nvfp4 | 738 MiB | 5.5% | **-1~-2%** |
| k8v4 | 1,030 MiB | 7.6% | **-3~-5%** |

## 9. 外部校准点：原生 KVMem 作者的 52K 配方对照（v3.0 新增）

来源：KVMem 原生实现（llama.cpp `llama-kvmem-server`，"IQ3 配方"启动脚本 + 容量模型教学页，2026-10 视频截图）。**他的世界没有异步页流水**——池是"覆盖下界配方"，超池即劣化。

| | 作者（原生 KVMem · IQ3 配方） | 本线（Ninfer-KVMem-Async） |
|---|---|---|
| 逻辑上下文 | 262,144 | 262,144（同） |
| KV 精度 | **q8_0 全档**（llama.cpp 口径 34.0 KiB/tok） | rk2v4-e8（13.0 KiB/tok）→ 目标 nvfp4 / **rk8v4** / Q8（本线 int8 实测 33.0 KiB，§1） |
| 池 | **52K**（36K 历史 + 16K 生成） | 81.9K（rk2v4 实测上限）/ **现生产 65,536（IQ3_S + rk8v4）** |
| 池字节 | ≈1.76 GiB | ≈1.04 GiB（贴边 1.06 GiB） |
| 搬运 | 同步（"不要小于 32K"= 池必须覆盖窗+检索） | **v2 异步页流水**（74.4K 深超池 114.4 tok/s 实证） |
| 速度 | 40-100 tok/s 级 | 极值 400+（记录 463.9）/ 1h 均值 220 |
| 视觉塔 | 不上卡（`--no-mmproj-offload`） | 不上卡（overlay）——同结论 |

**他的推算链（纯结构，无实测标定）**：`36,864 = 32,768（window） + 4,096（检索）`；`16,384 = -n 上限`；"不要小于 32K" = 经验下界（=window）。
**缺项**：多轮堆积容差（页漂移）、搬运时序维度。
**结构性收敛（互证）**：他的"36K 历史"与本线工作集（sink 5.1K + window 32K + 检索 4K ≈ 42K）几乎同构——两个独立实现都收敛到"池 ≈ 窗 + 检索（+ 生成预留）"。
**他的可借鉴主张**：**KV 精度值钱**（q8_0 全档，池字节给到 1.76 GiB）——本线 rk2v4 的质量代价至今未测（§8 清单）；与 §7.7"nvfp4 免费档"是同一命题的两端。
**Q8 档直接对照（v3.1 补 · v3.2 更新数）**：他的 **52K @ q8_0** —— 本线同精度可达 **IQ3_XXS + 102.3K（≈2 倍）**、IQ2_XS + 151.9K（§7.7）；同为 8bit KV，本线凭异步流水 + 换小权重档把池做大一倍以上。

### 10.2 逐字一致门（4-bit 的 agent 红线）

方法：同一批提示、温度 0、固定 seed、逐字对比（8 组）——PPL 跑不通的制品用它。结果：

```
int8（对照）   7/8 一致   一个词不同（引擎噪声基线）
rk8v4          5/8 一致   改写级；一组事实分叉
rk4v4-e8       3/8 一致   改写级；举例选择都变了（nvfp4 同族）
```

限定与判词：① **精确型任务（代码、长引用逐字、JSON）三个格式全一致**——本线 DSH 的主粮在安全侧；② 其试验在 1.58bit 权重模型上（分布更脆弱），本机 Q2Lynn 3.89bpw 的敏感度待自测；③ 其判词："分叉已到'选哪个事实'的层面，**对靠工具调用吃饭的 agent 是红线**"。⇒ 本线采用：**nvfp4 上生产前必过 §8 逐字门**。

### 10.3 口径纪律（两条直接影响本库）

- **"309,947 字/秒是除法不是算力"**：客户端把前缀恢复（~0.56s、命中 94%）当成了计算吞吐。⇒ 本库"220 tok/s / 400+ 极值"后续须标注口径：**冷算 decode / 缓存恢复 / 可预测输出**（其自纠："decode 103 只是可预测输出，散文是 35.2"）。
- **测量区间教训**：其曾在 96K 上得出"加大池反而更慢"——**台阶之外看不见台阶**（错误结论后被围绕拐点细采推翻）。⇒ 本库池扫描必须围绕 42-96K 拐点细采（§8 批 1 设计据此修正；v3.3 按实测请求线扩展上界）。

### 10.4 其他可借鉴（一句话版）

- 预填充"台阶" = `budget + gen-reserve` 窗口：真实负载越台阶掉速一半、抬高后 **+92%**——与 §7.6 甜点区同构；其 **81,920 也起不来**（"引擎预留核算差 294 MB"），与本库 98,304 被拒 -134 MiB 同类瓶颈。

2. 接受率 / tok每轮 / decode / TTFT（"tok/轮 恒 16.0"是 Q2Lynn + 固定 draft 几何的产物）；
3. **逐字一致门**（新工具 `scripts\verbatim_gate.py`，8 组固定提示 + argmax + 独立起服）：**同模型内** ≥7/8 过；**跨底座差异属预期**（首测：Q2Lynn vs Swift-IQ3_S = **1/8**，唯一全等者 = p5 逐字复述——精确型任务的安全侧与第三方结论一致）；
   - ⚠️ **适用域（2026-10-14 夜新增）**：逐字门与一切"内容不变"结论**只在「工作集 ≤ 池」条件下有效**——深上下文实测（60K，池 40,960 超池 19K）同格式输出即与装得下的臂不同（`78bcb798` vs `8b3a141f`）：超池 ⇒ 检索/选页介入 ⇒ 模型看到的是选出的子集（**设计行为**，非损坏）。⇒ 门禁/对账一律在"池 ≥ 上下文"下落跑。
4. 谷负担倍数（demote 字节随精度 ×1.4–2，谷期是裁判点）；
5. 质量/任务分（真实 DSH agentic 任务一条，两件各一轮）。

### 11.4 换档纪律（一次一变量，禁止并换）
**先"零换模型"的 KV 精度升级**（nvfp4 免费档 + 逐字门）→ **再做 KV A/B**（nvfp4 / rk8v4 / 现状）→ **最后换底座**。§3.3 已明确"两边量化损失都不大、差异主因在底座"⇒ 若同时换底座与精度，出问题将**无法归因**。
